# 数据与文件格式规范

> 桩。步骤 1 开工前（第 1 周）写完会话、账本与目录布局章节；其余章节在对应步骤填写。每种格式配 JSON schema 与读写测试，二者与本文同步改。来源：计划 4.10 第 1 行。

## 目的与范围

一句话：定义 `.nexgent/` 下所有持久化文件的格式，使会话、账本、能力版本、材料与成果能跨进程、跨版本读回。

## `.nexgent/` 目录布局

一句话：`sessions/ materials/ outputs/ capabilities/ ledgers/` 各自存什么、按什么命名、谁负责创建。

## 项目配置文件

一句话：项目级设置（模型、端点、沙箱模式、费用上限、自动改进开关）的文件名、字段与默认值。

## 会话 JSONL v1

一句话：记录类型、每条记录的必填字段、追加与截断规则、checkpoint 的触发与内容、按会话 ID 恢复的算法、同一会话的并发写保护；只定义 v1，不做迁移。

## 账本记录

一句话：每次模型请求一条记录（模型、端点、用量或 unknown、耗时、结果），任务结束一条 `task-outcome`；预留 `capabilityVersion / memberId / executionForm / taskId` 字段供步骤 4 填充；不记提示正文与密钥。

## `CapabilityBundle` 清单

一句话（步骤 4 填）：内容寻址的能力集清单，含工具、技能、上下文策略、协作方式四类组件及采用状态。

## 材料元数据

一句话（步骤 2 填）：`materials/<id>/` 的来源、类型、添加时间与引用方式。

## 成果元数据

一句话（步骤 2 填）：`outputs/` 每轮快照与 `present` 声明的对应关系、版本号与反馈关联。

## 版本与兼容

一句话：每种格式的版本字段、升级时的兼容规则（当前只有 v1，不兼容旧 Python 数据）。

## schema 与读写测试

一句话：每种格式的 JSON schema 存放位置、往返测试与截断 / 损坏文件的测试要求。
