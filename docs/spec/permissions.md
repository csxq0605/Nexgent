# 权限与审批模型

> 桩。步骤 1 开工前（第 1 周）写完沙箱模式、路径与命令策略、密钥存放与已知边界章节；其余章节在对应步骤填写。审批交互在桌面应用与 CLI 共用一套。来源：计划 4.10 第 2 行与“安全”一行。

## 目的与范围

一句话：定义 Nexgent 在用户机器上能读什么、写什么、跑什么、花多少钱，以及每一项由谁、在何时批准。

## 沙箱模式

一句话：只读 / 工作区写 / 完全访问三种模式的含义、默认值与切换方式。

## 路径策略与写入限制

一句话：工作目录白名单、`.nexgent/` 的例外、`..` 与符号链接逃逸的处理；Windows 先用路径策略，ACL 隔离后补。

## 命令策略

一句话：`bash` / `pwsh` 工具允许与拒绝的命令形态、超时与进程树终止。

## 工具审批

一句话：哪些工具调用需要用户确认、确认的粒度（一次 / 本会话 / 本项目）与记录方式。

## 插件安装审批

一句话（步骤 4 填）：插件包在宿主进程内执行，每次采用都需人审批；技能与 PTC 函数自动采用。

## 费用上限

一句话：每任务与每项目的调用数与 token 上限的配置格式与达到上限时的行为（步骤 1 只定格式）。

## 密钥存放

一句话：`NEXGENT_API_KEY` 与本机凭证文件的位置、权限与优先级；密钥不进会话与账本。

## 本地 IPC 与访问令牌

一句话（步骤 2 填）：Electron 渲染进程与主进程之间的调用边界与令牌。

## 已知边界与绕过

一句话：如实列出当前不能防住的情况，含 Windows 路径策略弱于 ACL、插件包进程内执行、完全访问模式。

## CLI 与桌面应用共用的审批交互

一句话：同一审批请求在 CLI 与桌面应用中的呈现与应答协议。

## 测试

一句话：每条策略对应的两平台测试要求。
