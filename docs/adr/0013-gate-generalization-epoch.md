# ADR 0013：门控新纪元：同类题不得变差，含原题具体数值的组件直接退回

- **状态**：已接受
- **日期**：2026-10-14
- **依据**：用户 2026-10-14 07:20 对审计（资料库 `docs/handoff/step6-generality-audit.md`）第 3 问回复“按推荐”，即 A：作为新的评分规则加两条，在没见过的同类题上不得比原来差；写进原题具体数值的规则直接退回。
- **替代**：
  - ADR 0006 中改进作业候选的采用条件，在下文第 1 条之上追加；
  - ADR 0008 第 5 条的规则 id `adr-0008`，改为 `adr-0013`，因此进入新纪元。
  - ADR 0005、0006、0007、0008 的其余部分仍然有效：确定性检查、反馈检查、守护集、费用规则、`decideImprover`。

## 背景

改进作业的候选在门控里主要靠原题验收：选择集的第一题就是收到反馈的那道题，回放到第一条反馈之前，再由评审判断反馈说的问题是否解决（`packages/capabilities/src/trial/feedback.ts`）。守护集只防“最不相似的旧任务”退步，不检查“相似但没见过的任务”。

结果是，把这道题的答案写进组件也能抬分。2026-10-14 的试跑里，子臂的上下文策略写了 “self-check East=4/2384.13 and North=5”。这对下个月的报表毫无用处，却提高了门控得分。

MASS 也观察到：内层优化会产生贴题的工作流，但它在留出的任务和不同种类的基准上评估结果，并且不拿测试题调。

## 决策

1. **同类题不得变差。**
   - 对象：改进作业（`origin: "improvement"`）的候选。
   - “同类题”指选择集中除反馈原题以外的用例。它们由相似度挑出，提案会话没有见过。
   - 采用（任何理由：`quality-up`、`cost-down`、评审打平后的偏好）都要另外满足：
     1. 同类题上候选的确定性检查通过率不低于基线；
     2. 同类题上没有 `unknown` 的运行。
   - 不满足时不采用，原因 `similar-regression`。同类题上有 `unknown` 时，结论按现有规则记为 unknown。
   - 选择集里没有同类题（项目历史里没有相似任务）时，不自动采用，改为等用户批准（`await-approval`，原因 `no-similar-cases`）。界面写明“只在原题上验证过”。
   - 用户在自己的任务里提出的候选（步骤 4 的路径）不受这一条影响。
2. **含原题具体数值的组件直接退回。**
   - **具体数值**：在下列“原题来源”里出现的任一词元，而且不在项目历史中至少两个不同任务的用户消息里出现。
     - 词元：带小数点的数、三位及以上的整数、日期或年月（如 `2026-10`、`2026-10-05`）。
     - 原题来源：作业的反馈原文；反馈原题会话交付的成果文件（各版本）。
     - 在两个以上任务里都出现的值算项目常量（例如固定的阈值），不算原题答案。
   - **检查点**：
     1. 改进作业里调用 `capability_propose` 时，宿主检查组件全部文本文件。命中即拒绝，返回命中的值和来源，会话可以改后再提，次数沿用现有上限。
     2. 门控开始回放之前再查一次。命中则不回放、直接拒绝，原因 `instance-literal`，不花回放的钱。
     3. ADR 0012 第 5 条的改进器改动检查用同一个函数。
   - 函数是 kernel 契约里的纯函数，输入组件文本与来源文本，输出命中列表。
   - 第一版只认数值与日期，不认名字与列名：列名、文件命名规则这类“约定”是项目规则的正当内容。
3. **新纪元。**
   - 评价器规则 id 改为 `adr-0013`，纪元 id 随之改变。
   - ADR 0008 第 5 条的跨纪元规则照常适用：新旧纪元的门控结论、父子比较与报告不放在一起。
4. **不在本 ADR 里的事**：
   - 反馈检查逐条打分；
   - 评审能看到输入文件；
   - 组件单独重做验证（审计 #16、#18、#19）。
   - 它们都会改变评分或作业流程，需要用户另行决定。决定之前不做。

## 后果

- 背答案的组件在提案时就被挡下，门控不再因此加分。
- 正当的项目约定（列名、口径、文件命名规则）不受影响。
- 小项目历史少，“没有同类题”的情况会常见，这时候候选要等用户批准，自动采用会变少。这是有意的：只在一道题上验证过的规则，不该自动成为长期规则。
- 同类题由相似度挑出，挑得不准时这一条会偏严或偏松。报告里单列 `similar-regression` 与 `no-similar-cases` 的次数，供以后调整。
- 步骤 5、6 的验收脚本里，期望“自动采用”的场景要确认选择集里有同类题，没有的要改期望或补历史任务。
