# ADR 0012：改进器改为用户级，所有项目共用一条版本线；能力组件仍留在各自项目

- **状态**：已接受
- **日期**：2026-10-14
- **依据**：用户 2026-10-14 07:20 对审计（资料库 `docs/handoff/step6-generality-audit.md`）第 2 问回复“按推荐”，即 B：所有项目共用一个改进器，能力规则仍留在各自项目。
- **替代**：
  - ADR 0008 第 1 条中“项目级、单独一条版本线”“存放在 `.nexgent/improvers/`”。改为下文第 1 条。
  - ADR 0008 第 3 条中元改进作业的计数范围、作业位与预算的“每项目”口径。改为下文第 3 条。
  - ADR 0008 第 4 条中“起点作业取自本项目”的隐含前提。改为下文第 4 条。
  - 步骤 6 分工表“已定的决定”第 1 项。
  - ADR 0008 的其余部分（改进器内容、能改什么、比较规则、纪元、记录格式）与 ADR 0009、0010 仍然有效。

## 背景

改进器的作用是让“怎样诊断反馈、提什么组件”变得更好。这件事与具体项目无关。项目级改进器有两个问题：

- 一个项目里的改进作业很少，元改进要么没有证据，试跑两次都判“不用改”；
- 要么只学到这个项目的题目：子版第 8 段以“扣退货”为例，并要求“确保组件改变失败检查所看的行为”。

MASS 的优化者通过权重整体变强，改进天然跨任务；我们不能改权重，所以至少要让改进器在用户的所有项目上积累证据。

## 决策

1. **改进器是用户级的。**
   - 版本线放在 `<NEXGENT_HOME>/improvers/`（默认 `~/.nexgent/improvers/`），布局与 ADR 0008 相同：`bundles/<version>.json` 与 `activation/<n>.json`，写入方仍是 `@nexgent/capabilities` 的 `ImproverStore`。
   - 同一台机器、同一个 `NEXGENT_HOME` 下的所有项目，用同一个生效的改进器。
   - 作业开始时固定版本，规则不变；`job.json` 与账本另记 `improverScope: "user"`。
   - 能力组件（技能、工具、上下文策略等）仍是项目级，仍在 `.nexgent/capabilities/`。一个项目学到的规则不会进另一个项目。
2. **旧的项目级改进器只读。**
   - 已有项目的 `.nexgent/improvers/` 不迁移（沿用计划 4.9“不迁移旧数据”），只用于查看历史。
   - 新作业一律读用户级版本线；用户级没有记录时用 `v0`。
3. **元改进作业按用户计数、按用户计预算。**
   - 计数：用户所有项目里结束的能力作业合计，每 3 个（`everyJobs`）开始一次元改进作业。计数规则与 ADR 0008 第 3 条相同，计入的作业以 `(projectId, jobId)` 记在用户级队列里，重启不重计。
   - 作业位：同一时间整个用户只有一个元改进作业；它与各项目的能力作业互不占位。比较臂在起点项目的副本里跑，不占真实项目的作业位。
   - 开关、`everyJobs`、元改进预算（默认每 30 天 600 万计费 token，约 6 美元）移到用户级配置。写入仍要审批。默认仍关。
   - 每个项目新增设置 `improvement.shareImproverEvidence`，默认开。关掉后，这个项目的作业不计数、不被元诊断读取，但仍使用共享的改进器。
4. **元诊断读多个项目的作业。**
   - 元诊断会话可以只读地查看本批计入作业所在项目的作业记录、会话与账本。工具多一个 `projectId` 参数，只能取本批涉及的项目。
   - 比较起点按 ADR 0009、0010 的规则，在本批涉及的所有项目里找，两臂在起点项目的副本里跑。
5. **改进器的文字不能夹带项目内容。**
   - 元提案改动的文字（段落、简报模板）按 ADR 0013 第 2 条做“具体数值”检查，检查对象是本批所有作业的反馈原文与成果文件。命中即退回，写明命中的值。
   - 这条检查既防背答案，也防一个项目的数据经改进器流到另一个项目。
6. **SDK 与界面。**
   - `improvers.list / show / rollback` 改为用户级，不再要求 `projectId`。
   - `improver.version` 事件改为应用级。
   - 改进页显示每个作业所用的改进器版本与范围。
   - 设置页分成两处：用户级的“改进器与元改进”，项目级的“参与改进器学习”。
   - SDK API 版本加 1（7）。

## 后果

- 元改进的证据来自所有项目，“改进器学成某道题的答案”的风险下降；具体数值检查进一步挡住项目内容流入改进器。
- 回滚改进器影响所有项目。界面要写明这一点，回滚确认框列出最近使用过它的项目。
- 实验必须给每个任务族、每个臂单独的 `NEXGENT_HOME`（ADR 0011 第 9 条），否则会互相串。
- 一个项目里的坏反馈可能把共享改进器带偏。门控、父子比较、纪元冻结与回滚仍然把关；用户也可以对单个项目关掉“参与改进器学习”。
- 多台机器之间不同步改进器，本步不做。
