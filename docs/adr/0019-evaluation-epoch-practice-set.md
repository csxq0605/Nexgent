# ADR 0019：评价纪元 `adr-0019`——在练习题集的留出题上打分，“更省”不算进化，怎样才算进化

## 背景

旧门控的“质量提高”全部是同一道反馈原题上的反馈检查从 0% 变成 100%，也就是“这条抱怨修好了”，回答不了“做事能力有没有变强”。“持平且更省”被当成采用，Mac 试用里唯一一次采用就是这种。递归改进的比较每臂只跑一次，信号是噪声。

## 决策

1. **质量 = 练习题集留出题上的得分。**
   - 得分 = 确定性检查通过率与冻结评分要点得分的组合，组合方式写进契约，纪元内不变。
   - 对由反馈引出的条目或技能，“原题修好”是必要条件，不是充分条件。
2. **第 2 层技能的验证。**
   - 在来源任务和相似的留出任务上，与“没有这个技能”对照，每边 3 次，按题配对。
   - 相似留出题的平均得分要提高；不相似的留出题与通用题不得变差。
   - 在两边得分都一样的评分要点（没有区分度）不计入。
   - 质量打平时，用 ADR 0016 的两两评审裁决；仍打平则不启用。
3. **“更省”单独记账。** 质量打平而更省的候选可以启用，但记为 `cost-optimized`，界面和报告里不计入进化次数，只计入省钱。
4. **第 3 层改动的验证。**
   - 留出集上按题配对的得分差，两层自助法 95% 区间下限大于 0；
   - 通用题不得变差；
   - 满足后等用户批准（ADR 0018 第 9 条）；启用后在真实任务上持续监测，退化就自动回滚（沿用 ADR 0005 决策 6 的机制）。
5. **改进器的比较。** 改进器版本的好坏，用它带出来的第 1、2 层产出在留出集上的收益衡量：多个起点，每臂多次运行，用配对区间判定。取代每臂一次的父子比较。
6. **评分器的可靠性。**
   - 产品自评与外部评审（`claude-opus-5-5`）在抽样上的一致率，按项目和总体记录。
   - 一致率低于 80% 时，判为“评分不可靠”：第 2 层技能不自动启用，改为等用户批准；第 3 层不运行。界面写明原因。
   - 抽样比例和花费计入 ADR 0018 第 10 条的预算。
7. **评价器不归改进器改，按纪元冻结。** 规则 id `adr-0019`，纪元 id 随之改变。新旧纪元的结论、比较与报告不放在一起。
8. **怎样才算“进化了”（测量判据，开跑前冻结）。**
   - 对照臂：base（不学习）、format（只换提示格式，不放内容）、notes（原样记笔记）、L1（只有手册）、L1+L2（手册加技能库）、L1+L2+L3（再加离线进化后的框架）。
   - 任务：做法类任务，6 类，其中 2 类整类留出；每题评分要点里约定类至多 1 个。
   - 判据：
     1. L1 − notes、L1+L2 − L1 的区间下限都大于 0，才能说这一层有用；
     2. 在整类留出的任务类型上 L1+L2 − notes 的区间下限大于 0，才能说“进化了”；
     3. L1+L2+L3 − L1+L2 在留出集上大于 0，才能说“递归改进”；
     4. 背答案率为 0；`cost-optimized` 不计入；
     5. 报告所有变差的类别。
   - 外部评审只做报告，不进循环。
   - 判据或题目在开跑后改动，就作废这一轮，换新的实验 id。

## 后果

- 门控的输入从“反馈原题加相似题”变成“练习题集的选择与留出”；小项目历史少时，靠用户级题集和通用题补足；都不够时技能等用户批准。
- 旧纪元（`adr-0013` 至 `adr-0016`）的试点结果不能和新结果直接比较。
- 验证要跑多次，第 2 层作业比旧作业贵；由每项目 3 美元的预算和单作业上限约束。
- “进化了”的说法只在第 8 条判据满足后，才能出现在验收记录和根 README 里。
