# ADR 0028：改进在后台进行，界面只讲结果

- **状态**：已接受
- **日期**：2026-10-19
- **依据**：用户 2026-10-19 试用后指出：页面文字太多，说明文字一直显示；主要功能不突出，所有功能平铺，看不出哪个是核心；可以设置限制的地方太多。改进应该润物细无声，用户只需要知道改进了什么、现在怎样、效果如何。
- **替代**：ADR 0020 第 1 条中“能力页分经验、做法与版本、改进记录、离线改进四个标签”的结构；各设置项说明常显的做法。

## 决策

1. **能力页只有一页，自上而下是：**
   - 一句总结：用着几条经验、几条项目规则，最近一次改进在什么时候；有对照记录时，再给一句效果，即用上经验的任务比没用上的结局好多少（满分 100）。
   - “等你看一眼”：只在有事要用户决定时出现，包括待确认的项目规则、要用户同意才启用的新做法、离线改进找到的更好版本。
   - 项目规则：每条一行，带适用范围。
   - 正在用的经验：每条一行，带“用过几次”，点开才看经过。
   - 最底下是折叠的“改进记录”，收着试用中和停用的经验、学习开关与费用、做法与版本、一次次改进、离线改进的计划与运行。别处跳到某一部分时，自动展开那一部分。
2. **说明文字不常显。** 设置项和卡片的说明放在名称旁的问号里，鼠标悬停或聚焦时显示；只有错误和需要用户决定的事才常显文字。
3. **设置页只露常用的。** 默认展开通用、模型、权限三组；完成检查、费用上限、自动改进的预算与共享收进折叠的“高级”，默认值自动生效。
4. 后台机制不变：学习、随机对照、门控、离线改进的规则与数据格式都不动，只改界面的组织和文字。

## 后果

- 桌面层测试里按标签切换能力页各部分的步骤，要改成展开“改进记录”。
- 想细看机制的用户仍能在“改进记录”里看到全部信息。
