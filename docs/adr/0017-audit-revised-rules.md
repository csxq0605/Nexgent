## 背景

审查发现，这六条当初各有理由，但在真实项目和长任务里都成了障碍：

- 编辑工具太严，模型一直绕开它们改用 bash 写文件，安全没有得到，效率反而损失（审查 P8）；
- 一次 429 或断网就结束整轮（P1）；
- 后台改进默认开，3 条差评就在用户不知道的情况下花约 3.8 美元，是任务本身的 5 倍，关掉应用还在跑（P6）；
- 对话记录、账本、快照写在用户项目里，`git add -A` 会把它们提交出去（P7）；
- 一次读 8 个文件也要逐个等，同一条回复里的多个委派一个接一个跑（P13、P17）；
- 费用上限按 token 计，中断的请求记 0，界面上看不到花费（P16）。

## 决策

1. **编辑工具放宽，提示不再禁止 shell 写文件。**
   - `write_file` 可以覆盖本会话读过的文件，或调用时带 `overwrite: true`；覆盖前的内容照旧进入成果和变化记录。
   - `str_replace` 增加 `replace_all`，并允许一次调用给出多处编辑（全部成功才写入）。
   - `read_file` 输出带行号。
   - 系统提示与 bash 工具说明里“禁止用 shell 写文件”改为“改文件优先用编辑工具”。这条原本来自步骤 2 R02 一次运行的模型习惯，属于用例特化。
2. **模型请求按退避重试。**
   - 429、5xx（含 529 过载）、连接中断和超时按指数退避重试，遵守服务端的 `retry-after`，次数与总等待时间可配置。
   - 每次尝试各记一条账本，“每次请求一条账本”的原则不变。
   - 实现由「kernel 维护」在长任务修复（审查 P1–P4）里完成。
3. **后台学习默认开，但先告知、有上限、看得见、随应用停。**
   - 旧的“3 条信号触发独立进程改进作业”退役，由 ADR 0018 的三层进化取代。
   - 第一次在某台机器上使用时，开始任何学习花费之前，界面告诉用户：后台会自评和学习，每个项目每 30 天最多花多少美元，在哪里关。用户确认一次即可，不必每个作业都问。
   - 学习花费在对话界面和能力页上看得见，按美元显示。
   - 后台学习在应用进程内或其子进程里运行，应用退出时一起停止，下次启动再继续；不留下关窗后仍在花钱的进程。
   - 每个任务的自评花费有单独的上限（ADR 0018 第 2 条）。
   - 审查原建议是“默认关，或攒够阈值先问”。这里选择默认开，是因为用户同时批准了“允许自评”和“日常预算沿用每项目每 30 天 3 美元”（ADR 0018）；审查担心的三件事（不知情、花费远超任务、关了还在跑）由告知、上限、可见和随应用停四条解决。
4. **数据移出用户项目。**
   - 会话、账本、快照、资料副本、改进记录、“本项目总是允许”的授权，统一放到用户数据目录 `<NEXGENT_HOME>/projects/<projectId>/`。
   - 项目里的 `.nexgent/` 只保留可以和同事共享的内容：`project.json`（含稳定的 `projectId`）、不含授权的项目配置。
   - 旧项目第一次打开时迁移：复制到用户数据目录，校验后在旧位置留一个说明文件；旧数据不自动删除，删除要用户同意。
   - 迁移完成前或用户选择保留旧数据时，自动写入 `.nexgent/.gitignore`，除共享配置外全部忽略。
5. **只读工具与多个委派并发。**
   - 同一条回复里的只读工具调用并发执行；多个 `delegate` 并发执行。
   - 需要审批的调用仍按原顺序串行。
   - 结果按原顺序交回模型，记录顺序与现在相同。
6. **费用上限按美元计。**
   - 上限按价目表（`prices.ts`）折算的美元计；缓存读、缓存写、输出按各自单价算，不再等价计 token。
   - 中断或出错的请求按已知用量计入；流里没有用量时按已收到的内容估算并标为估算。
   - 达到上限的 80% 时预警；界面显示数字和美元。
   - `perTask` 指一个根任务（含其成员）；整段对话的累计另设 `perConversation`。
   - 改了设置，从已打开对话的下一个根任务起生效。

## 后果

- 规范 `data-formats.md`、`permissions.md` 和对应契约要改，旧项目要迁移；迁移失败时不动旧数据，照旧可读。
- 依赖“`write_file` 拒绝覆盖”“请求不重试”“费用按 token”的测试要改期望，由「测试与 CI」列出清单与理由。
- 并发后，同一回复里工具调用的完成顺序会变；记录与回放按调用顺序，不按完成顺序。
- 自动学习仍会花钱，只是用户知情、可关、有上限。
