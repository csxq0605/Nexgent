# ADR 0007：门控的费用规则——质量提高不因费用拒绝，按美元比较，过贵等用户批准

- **状态**：已接受
- **日期**：2026-10-13
- **依据**：用户 2026-10-13 12:22 回复“选C”（门控费用规则调研的选项 C）；步骤 5 真实模型第 1 次运行的门控结果。
- **替代**：
  - ADR 0005 决策 5 中“质量提高且 token 不超过基线 1.2 倍才采用”一句；
  - ADR 0006 决策 6 中沿用这一句的部分，以及决策 8 中“判断只用 token 与请求数”对门控费用比的适用。
  - 两份 ADR 的其余部分不变。改进预算、单个任务的费用上限仍按 token 计。

## 背景

步骤 5 真实模型第 1 次运行时，改进作业的候选质量更好：确定性检查通过率 100% 对 67%，反馈检查 100% 对 0%。门控仍然拒绝了它，理由是 `cost-over-cap`，token 比 1.555，超过 1.2。

这个比只算输入和输出 token。缓存读写约占全部 token 的 98%，没有计入。两臂的输入几乎相同，所以这个比实际上就是输出比。反馈本身要求多写内容，输出变多是改进的直接结果。按估算美元（含缓存）算，比只有 1.16。

调研（Library `docs/handoff/gate-cost-vs-paper.md`）没有找到把“质量更好但贵了 1.2 倍”作为硬性拒绝条件的做法：MASS、Darwin Gödel Machine 只报告费用，SICA 把美元费用作为一项分数和质量加权。

## 决策

1. **费用比按估算美元计算。**
   - 每臂的美元来自 `@nexgent/llm` 的只读价目表（`estimateUsd`），含缓存读写。
   - 两臂的美元都已知、且基线大于 0 时，费用比 = 候选美元 / 基线美元；否则退回 token 比（输入 + 输出）。两者都未知时，按 ADR 0006 规则判为 `unknown-runs` 并拒绝。
   - 判定结果 `TrialVerdict` 新增 `costBasis: 'usd' | 'tokens'`，写明 `costRatio` 用的是哪种单位。
   - 门控结果的说明文字给出比值和两臂的美元估算，“改进”页通过决定的说明文字显示出来。
2. **质量提高时不因费用拒绝。**
   - 质量（确定性检查与反馈检查合计的通过率）高于基线时：费用比不超过 `costApprovalRatio`（新设置，1–10，默认 2）就直接采用（`quality-up`）。
   - 超过时不拒绝，改为等用户批准：结论 `await-approval`、理由仍是 `quality-up`，沿用插件候选的待审批流程（`capabilities.approve`）。说明文字写明“检查更好，但费用是基线的 X 倍”。
   - 质量提高时不再出现 `cost-over-cap`。这个理由值保留在枚举里，供读旧记录。
3. **质量打平时规则不变。**
   - 费用比 < 1 采用（`cost-down`）。
   - 否则由评审模型投票，投票偏向候选、且费用比不超过 `costRatioCap`（默认 1.2）才采用（`review-preferred`）。
   - 其余情况拒绝（`no-improvement`）。
   - `costRatioCap` 只在这一步起作用。比较单位同决策 1。
4. **其余不变。**
   - 守护集不得退步；任何 `unknown` 都拒绝；插件候选仍要审批。
   - 单个任务的费用上限、改进预算（按 token、30 天时间窗）不变。
   - 采用后的退化回滚不变：只看检查通过率与新组件的连续出错次数，不看费用。
5. **记录。**
   - `TrialPlan` 冻结 `costApprovalRatio`（ADR 0007 之前的试验没有这个字段）。
   - `.nexgent/config.json` 的 `capabilities.costApprovalRatio` 可以调整这个倍数。
   - 纯函数 `decideTrial(tally, costRatioCap, costApprovalRatio)` 固定这一规则，`TrialTally.usd` 是每臂的美元估算。

## 后果

- 质量更好但输出更多的候选不会再被一个噪声很大的比值静默拒掉。明显变贵的候选交给用户决定，用户在批准时看得到费用倍数。
- 自动采用的能力最多可能让每次任务的费用翻倍，前提是检查确实更好。如果担心长期变贵，可以以后增加“采用后费用明显上升”的提醒，这次不做。
- 美元估算依赖只读价目表。价格变了比值会跟着变；价目表里没有的模型，或用量缺少缓存字段时，退回 token 比。
- 桌面的审批对话框原本只为插件设计，非插件候选（因费用过高而待审批）的文案需要「SDK 与桌面」跟进。
