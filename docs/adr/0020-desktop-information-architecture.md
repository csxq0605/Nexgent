# ADR 0020：桌面界面改为两栏加按需抽屉，术语改人话，生成文字用用户的语言，深浅两套配色

- **状态**：已接受
- **日期**：2026-10-16
- **依据**：用户 2026-10-16 14:45 指出界面难看、功能堆叠、描述堆叠又压缩不清楚；15:31 回复“你自己看着按推荐和想法来，要综合”，对象是资料库 `docs/handoff/ui-redesign-research.md` §7 的 5 件事。视觉稿：https://claude.ai/artifact/8YygwdWW7D4GJ8EkX3aPZE 。
- **替代**：步骤 2–6 分工表里右侧常驻面板（资料、成果、文件、目标、能力、改进 6 个标签）的界面结构。ADR 0001 中“Electron + React 桌面应用”的决定不变。

## 背景

主要问题在信息架构：一屏三栏，320px 的右栏塞 6 个标签，门控、改进器、元改进这些专家内容用 11–12.5px 的小字往下堆；对话流里工具调用逐条摆出，同一批文件列三遍；内部术语和后端英文直接给用户看；`styles.css` 有 15 种字号。

## 决策

1. **去掉常驻右栏。**
   - 主界面两栏：左栏（项目、新对话、对话列表、底部“能力”“设置”）和对话。
   - 资料与成果放进按需打开的右侧抽屉，默认关闭。
   - 能力（含学习与改进）和设置各做成整页，替换中间区域。
   - 过程默认折叠成一行摘要；成果卡与审批卡在对话流里；审批改为内联卡片，最多三个按钮。
2. **界面术语改人话，只改界面文字。** 代码、规范、ADR 里的术语不变。

   | 内部 | 界面 |
   | --- | --- |
   | 门控、门控试验 | 对比测试 |
   | 候选 | 新做法 |
   | 采用 / 未采用 | 启用 / 没有启用 |
   | 基线 | 原来的做法 |
   | 能力版本哈希 | 第 n 版（哈希放进详情） |
   | 改进作业 | 一次改进 |
   | 改进器 | 改进方式 |
   | 元改进、第 3 层 | 改进“改进方式”、深度改进 |
   | 经验手册条目 | 经验 |
   | token | 美元（token 作灰字附注） |

3. **左栏改浅灰。** 中性灰为主，一个强调色；状态用小圆点加文字，不用彩色胶囊。字号只用 4 级（12、13、15、20），字重 400 / 500 / 600。
4. **模型生成、给用户看的文字用界面语言。**
   - 反思、经验条目、技能描述、诊断、候选摘要、改进理由按界面语言写（ADR 0018 第 11 条）。
   - 对比测试结论、错误提示由界面按结构化字段拼成用户语言，不显示后端拼的英文句子；原文放进“详细数据”。
5. **深色模式这次一起做。** 用同一套颜色 token 的浅色和深色两组值，默认跟随系统外观，可在设置里固定。

## 后果

- 渲染层大部分组件要重排，分两轮做（重做分工表 D1、D2）。
- 能力页的内容取决于三层进化的输出（经验、技能、对比测试结论），所以第二轮要等对应契约落地后再做。
- 桌面层验收的选择器与截图基线要更新，由「测试与 CI」列出期望变化。
