# ADR 0023：经验有没有用，靠随机注入对照和外部结局判断

- **状态**：已接受（本 ADR 只定契约；实现由「能力版本」和「改进流程」接着做）
- **日期**：2026-10-17
- **依据**：
  - 资料库 `docs/handoff/redesign-proposal-2026-10.md` §1；
  - 用户 2026-10-17 对该方案回复“同意”。
- **替代**：
  - ADR 0018 第 4 条“计数”一项中，执行时的标记和反思者的推断算作有用 / 有害计数的部分；
  - ADR 0019 第 6 条中，评分器可靠时第 1 层条目按票自动启用的部分。
  - 评分器纪元不变：规则 id 仍是 `adr-0019`，门控与判分器不改。

## 背景

条目从试用转为启用，原来靠的是执行模型调用 `handbook_mark` 投的票，以及反思者按同模型自评投的票，两种都来自同一个模型。冒烟里一条条目拿到 7 张有用票、0 张有害票，但学习臂和笔记臂的分数完全相同，票和实际效果是脱节的。

文献给出的判断依据都来自对照：
- ExpeL 的票建立在环境真值上；
- skill-creator 和 gskill 用“有 / 无”对照；
- 同模型评审会偏向自己（2604.06996、MASS）。

## 决策

1. **模型自己的话只算“用到了”。**
   - `handbook_mark`，以及以同模型自评为依据的反思投票，照旧写成 `ops.jsonl` 的 `upvote` / `downvote`。
   - 条目的 `helpful` / `harmful` 从此读作“用到了” / “说它误导”，不再让条目启用。
   - “说它误导”只能把启用的条目退回试用。这是偏保守的方向。
2. **结局只认三种来源。**
   - 用户的明确信号：评分、指出问题的评论、改回或删除成果；
   - 确定性检查；
   - 外部评审在校准抽样上的打分。
   - 同模型自评不是结局来源，契约的枚举里没有这一项。
3. **随机注入对照。**
   - 根任务检索到一条试用条目，并且它通过了相关性门槛时，按概率 0.5 决定给不给模型。每个任务至多抽 1 条试用条目。
   - 启用的条目每个任务至多给 4 条，仍按 0.9 的概率给，留出 10% 用来发现退化。
   - 两种抽签结果都记录下来。
4. **状态规则**（`handbookStatusFromEvidence`）：
   - **启用：** 给和不给两组，结局已知的任务各至少 3 个，并且给的那组均分不低于不给的那组。
   - **下线：** 满足下面任一条：
     - 给的那组出现用户的负面信号；
     - 给的那组至少 4 个任务，均分比不给的那组低 0.1 以上；
     - 被取代；
     - 按使用情况下线（PR #197 的规则不变）。
5. **记录位置：衔接 `usage.jsonl`，不另起文件，也不重复记录。**
   - **展示：** 沿用 `hit` 行，新增 `draw`（`shown` / `held-back`）、`showProbability`、`status`、`taskId`。没有 `draw` 的旧行不算对照证据。
   - **结局：** 新增 `outcome` 行，每个根任务一行，写进这个任务有抽签记录的每一份 `usage.jsonl`。同一会话后写的那行算数。
   - `ops.jsonl` 的五种操作不变。

## 后果

- 转正会变慢：一条条目要攒够 6 个结局已知的任务才能转正。转正慢，好过转错。
- 旧数据照常能读。按票启用的旧条目保持现有状态。实现接上新规则之后，`nextHandbookStatus` 不再由宿主调用。
- 下游要做的事：
  - 「能力版本」：`HandbookHost.forTurn` 抽签并写 `draw`，试用条目单独列出，并标明“试用”。`handbookUsage` 的类型改从 kernel 导入。
  - 「改进流程」：任务结束后写 `outcome`；反思投票只记“用到了”。
  - 桌面能力页：显示“给出 N 次、未给出 M 次、结局差 x”。
