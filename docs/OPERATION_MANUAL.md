# Nexgent 操作手册

面向日常使用：打开项目、在总对话里把事情交给 Nexgent、看讨论串和成果、提修改、理解它什么时候组队、什么时候问你。

安装与打包见 [本地运行](RUN_LOCAL.md)，密钥、环境变量与数据目录见 [配置](CONFIGURATION.md)。开发约定见仓库根目录 [`AGENTS.md`](../AGENTS.md)。

---

## 1. 启动

```bash
# 在仓库根目录，先按“本地运行”构建一次
pnpm --filter @nexgent/desktop start
# 或直接打开一个文件夹
node apps/cli/bin/nexgent.mjs app --project /path/to/project
```

第一次启动时：

1. 在开始页选一个项目文件夹（或输入绝对路径新建）
2. 没有密钥时按提示粘贴 Anthropic API 密钥
3. 新项目会打开它的“总对话”，用平常的话说明想要的结果

---

## 2. 打开项目

开始页可以选一个文件夹，或输入绝对路径新建。项目就是你的一个文件夹，Nexgent 在里面读写文件、运行命令。最近打开过的项目列在开始页和左栏顶部。

---

## 3. 对话

窗口分两栏：左栏是项目切换、“新对话”和对话列表，最上面固定是“总对话”，讨论串挂在所属对话下面；底部是“能力”和“设置”。右边是当前对话。

- **总对话**：每个项目一个，是默认入口。它自己不改文件、不跑命令，只拆分、派讨论串、跟进、转达你的纠正、汇总结果。简单问题它直接回答。
- **讨论串**：总对话派出去的活，每个讨论串一张卡片（进行中、做完了、等你回复、等你批准、停了、没做成），点“进入讨论串”可以看它在做什么、直接跟它说话，顶上的“讨论串 · 属于总对话”回到总对话。讨论串在后台、在自己的项目副本里做，每轮做完把改动合回项目；做完的收进侧栏“已完成的讨论串（N）”一行。等你回复或等你批准的带黄点。
- **普通对话**：点“新对话”开的对话自己读写文件、跑命令，也会组队，适合不想经过总对话的小事。
- 在输入框里用平常的话说想要什么结果。要用文件的话，先点“附件”加进来，输入 `@` 可以引用已有的资料。
- 它在干活时，输入框照样能用：发出去的话下一步就生效，也会转给正在干活和接着开始的成员；在总对话里说的纠正会转给相关的讨论串。想让它停下就点“停止”，已经写出来的内容会保留。
- 干活的过程折叠成一行（思考、读文件、运行命令……），点开能看每一步。讨论串或普通对话组队时会出现一张“小组进度”卡，列出每个成员的角色和状态；换过分工时会写明原因。这一轮的组织比上次改了一处时，你的消息下面会有一行小字说改了什么、为什么。点成员旁的“看它的过程”可以只读查看它的对话。
- 想先看计划再动手，用“以计划模式开始”：它先只看不改，给出计划，你批准后才改文件。
- 每段对话可以设一个目标（一句话），完成或放弃都可以标记。

---

## 4. 资料与成果

- **资料**：加进来的文件会复制到项目数据里，原文件不会被修改。
- **成果**：它完成工作后用成果卡片交给你。可以打开、预览、在文件管理器里显示，也可以“对比上一版”。
- **提修改**：在成果卡片上点“不满意？告诉 Nexgent”，可以打分并写修改意见，它会出新版本。
- 右上角的“资料与成果”抽屉里有这段对话和整个项目的资料、成果、项目文件。

---

## 5. 批准

写项目外的文件、写敏感文件、运行沙箱外的命令等操作会弹出“需要你的批准”，可以允许一次、在本对话内允许、在本项目内允许，或拒绝。成员请求批准时会写明是哪个成员。

---

## 6. 撤回

在某条你发的消息上点“撤回之后的文件改动”，可以把这条消息之后 Nexgent 改过的文件恢复成发消息之前的样子。对话记录保留，可以接着聊，别的文件不受影响。太早的轮次没有留下文件快照时不能撤回。撤回之后，Nexgent 下一次回答前会知道哪些文件变了，先读文件再下结论。

---

## 7. 能力页

能力页说明 Nexgent 在这个项目里用着什么：

- 开头一两句话：用着几条经验和项目规则；同类任务用哪种分工更顺利、花费多多少（次数还不够时显示“还在比较”），次数够了还说组织调整后比一开始省了多少、快了多少。
- **等你看一眼**：从你的话里看不出是不是“以后都这样”时，会问你要不要当成项目规则。只在有事时出现。
- **项目规则**：你定下的规则和适用范围。
- **已学会**：正在用的经验，每条写明帮上忙几次、带偏几次，可以停用或恢复。
- **改进记录**（折叠）：学习开关与费用。

## 8. 设置

改动立即保存。

| 分组 | 内容 |
| --- | --- |
| 通用 | 外观（跟随系统、浅色、深色）；语言（Nexgent 写给你的经验和说明用哪种语言） |
| 模型 | 模型、先思考再回答、思考深度 |
| 权限 | 文件权限：只读、可写工作区、完全访问 |
| 完成检查 | 没通过时自动再改几次（默认 2 次）；检查命令（例如 `npm test`），每轮改过文件后依次运行 |
| 费用 | 每个任务、每段对话、整个项目的上限（美元，空着就是不限），也可以按 tokens 或请求次数限制 |
| 自动改进 | 每次任务后自己学习的开关；学习预算（默认每个项目 30 天 3 美元） |
| 高级 | 模型 API 密钥、数据位置 |

## 9. 它什么时候组队

| 情况 | Nexgent 怎么做 |
|---|---|
| 一行、40 个字或词以内、没有资料的小任务 | 总对话整件交给一个讨论串；普通对话自己做 |
| 其他任务 | 总对话按改不同文件拆成几个讨论串，至少一个做、一个随后检查；约五分之一整件交给一个讨论串，作对照 |
| 讨论串拿到的一块很小 | 自己做、自己查，不派成员 |
| 讨论串拿到的一块大 | 用 `organize` 分出 1–6 个成员 |
| 同类任务以前有效果好的分工 | 从那个分工开始 |
| 分工没有进展，或检查没过 | 换一种分工，“小组进度”卡上写明原因 |
| 几个讨论串都合回了项目 | 总对话派一个讨论串检查整个项目 |

不需要你选组队方式。每次组队做完，它自己按花费、耗时、失败找最费的一处，下次同类任务改那里，变好就留下，没变好就退回。

## 10. 命令行

```text
nexgent run --project <dir> --task "<text>" [--sandbox <mode>] [--model <id>] [--json]
nexgent resume <sessionId> --project <dir> [--task "<text>"] [--sandbox <mode>] [--json]
nexgent export <sessionId> --project <dir> [--out <dir>] [--json]
nexgent app [--project <dir>]
```

在仓库里用 `node apps/cli/bin/nexgent.mjs` 代替 `nexgent`。

- `run`：在项目里开一段新对话，做一个任务。标准输出只有回答，过程写在标准错误。
- `resume`：接着一段对话说；不给 `--task` 时就是“从停下的地方继续”。上次被强杀的轮次会先标成中断。
- `export`：把一段对话的记录、账本、资料与成果清单导出到一个目录，密钥会被替换成 `[REDACTED]`。
- `app`：打开桌面应用。
- `--sandbox`：`read-only`、`workspace-write`（默认）、`full-access`。
- `--json`：每个事件一行 JSON，最后一行是结果。

退出码：0 完成；1 没完成（模型或工具出错、费用上限、中断）；2 用法错误；3 环境问题（项目不存在、没有密钥、配置错误、会话被占用）；4 内部错误；130 用户取消；143 被终止。完整参数、事件格式与环境变量见 [apps/cli/README.md](../apps/cli/README.md)。

命令行用的是普通对话，没有总对话和讨论串。

## 11. 常见问题

- **窗口里只有“界面尚未构建”**：执行 `pnpm --filter @nexgent/desktop build`。
- **提示没有密钥**：设置环境变量后重启，或在设置页填写。
- **命令一直要批准**：在批准框里选“本项目内允许”，会保存成匹配规则，下次同类命令不再问。
- **macOS 上测试会弹出窗口**：desktop 包的界面端到端测试会打开真实窗口（macOS 没有虚拟屏幕），在 Linux 上跑这类测试即可。
