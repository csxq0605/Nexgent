# 重启科研协议：从真实失败到源码级科研智能体自改进

日期：2026-09-15。状态：**研究协议与接口建议，尚非新实现或新实验成功声明**。
本轮仅分析已有 Provider 运行产物并检索一手文献，没有新增模型服务调用，也没有改动旧数值或控制器代码。

定位说明（2026-09-16）：本文记录科研发现 demo 的历史设计、失败诊断和实验协议。Nexgent 本身是通用 RSI 智能体框架，任务、工具、数据和评价由独立 benchmark 插件提供；科学发现不是核心框架的领域限制。当前科学实现位于 [独立插件](../../benchmarks/scientific_discovery/README.md)，已完成六组研究的结果见 [批次报告](source-batch-results-20260916.md)。下文带日期的旧路径和实验记录保留其历史含义。

## 1. 本轮需要回答的问题

目标是能修改自身任务程序与改进程序、由后代继承并继续执行的通用 RSI 智能体框架。本协议在科学发现 demo 中研究这一能力。
上一实现把改进空间限制为固定枚举字段，并以一个简化邻域分数代理元能力。这种收缩没有充分实现上述要求。
本协议将源码级 task agent 和 improver 都作为真实执行和演化对象，保留独立评价边界，并要求通过对照实验检验递归改进是否带来额外收益。

阴性结果用于定位问题、修正研究假设和继续实验。保存一次阴性结果，并不等于实现目标已经完成。
同时，不能为了得到阳性结果修改已打开测试集的门槛、删除失败任务或只展示最好种子。

本轮的三个可证伪问题是：

1. 完整科研程序能否解决固定数值管线暴露的方程表达、噪声处理、模型选择与反例修复问题？
2. 演化后的 improver 是否比同预算的冻结 improver 更能生成有迁移收益的科研智能体源码？
3. 这种收益是否在两个以上真实继承步骤、多个独立演化种子和封存任务上成立？

### 2.3 不能丢弃的有效研究线索：C4

**观测事实**：扩展方程库帮助了非线性系统，但未在所有任务上成立。
**待验证解释**：三次库与带噪前向差分可能在本来线性的阻尼振子上引入伪项或传播导数误差。
现有数据没有单独消融导数、库、正则化和模型选择，因此不能把因果解释写成已证明结论。

下一实验应从新的公开 development 阻尼振子样本检验这些解释，比较局部多项式导数、弱形式、稳定项选择与完整预测验证。
不应为让 C4 通过而把旧 0.12 阈值改到 0.14；新的方法应实际修复退化。
原封存 promotion 数据的细节现已用于本次诊断，故这批数据应退役为诊断材料，不能作为新系统的盲测集。

### 2.4 旧 Meta 代理究竟测了什么

冻结 worker 实际执行的是：

```text
children = task_mutations(SEED_TASK_POLICY, meta)[:2]
selected = argmax(development_score(SEED_TASK_POLICY + children))
M_old = transfer_score(selected)
```

历史导出已经修复了“强行生成第二个后代”的早期 bug；本次失败不是那个已修复 bug 造成的。
本次问题是评价对象与声明对象不一致：

| 需要评价的能力 | 旧代理实际覆盖 | 缺失 |
| --- | --- | --- |
| 基于证据形成改进假设 | 固定函数按枚举字段顺序变异 | 没有执行真实 Provider 的证据分析、批评和设计 |
| 改写科研方法和智能体编排 | 切换少数参数与选项 | 没有生成、编译和执行新算法或智能体源码 |
| 改进已经较强的智能体 | 每次回到同一个线性基线 | 不测试不同水平、不同失败模式的真实父代 |
| 复用失败历史 | engine 给 proposer 的 history 为 `[]` | 被拒绝候选没有转成下一轮的公开反例研究 |
| 产生可继承的后代 | 固定 `task_mutations` 没有演化 | 改进程序源码并未被下一代替换执行 |
| 真实预算下的研究效率 | 至多两个枚举后代的数值计分 | 无真实 improver 模型调用、补丁失败和实验规划成本 |

C1 的代理选择出了 cubic / forward / fit，C4 的代理则选 quadratic / forward / fit。
所以旧门槛偏好“从弱线性种子跳到三次库的字段顺序”，并不等于偏好真实后续科研生产力。
C1 确实让后续邻域暴露了 cubic，这是一种有用但局部的搜索偏置；C4 也确实存在需要修复的科学退化。
两点都应保留，不能把失败单因归结为模型不够强，或者为了获得阳性直接撤掉回归检查。

## 4. 科学创新应落在哪里

恢复生成器已知的 Logistic 方程本身不是新自然定律。合成动力学的价值是提供可控反例、可靠真值与重复实验，让研究程序和自改进机制的创新可以检验。
项目可以提出新研究方法，但“创新假设”必须在强基线与消融后才能变成“得到证据支持的贡献”。

| 待检验创新假设 | 可执行改变 | 能否被推翻 |
| --- | --- | --- |
| H1：失败类型驱动的估计方法组合优于统一固定拟合流程 | 智能体根据残差结构、噪声和可辨识性选择或生成导数估计、弱形式和模型选择程序 | 同预算强基线已达到相同质量，或去掉诊断后差异消失，则假设不成立 |
| H2：主动寻找反例可使改进从平均分优化转成稳健科研能力 | 根据相互冲突的候选方程设计新初值、激励、采样与重复实验 | 同预算随机实验同样有效，或改进不能迁移到新观测，则不支持 |
| H3：从多种父代与失败轨迹学习的源码 improver 具有可迁移生产力 | 改写 improver 的检索、反例规划、补丁组织、测试选择与档案利用 | 固定 improver 在真实后代评估上相同或更好，则不能声称 Meta 改善 |
| H4：Task/Improver 的源码继承产生额外递归收益 | 新版本真实执行其 task 与 improver，继续形成第二、第三层后代 | 只改 Task 或冻结新 Improver 后曲线不变，则额外递归收益未证实 |

这些是本项目拟检验的组合方法，当前不声称“首次提出”。近邻文献与代码检索应随具体候选形成后补充，尤其检查是否仅重新实现既有 WSINDy、模型选择或程序搜索方法。

## 5. 科研流程必须对应真实动作和产物

| 阶段 | 输入 | 必须执行 | 输出及检查 |
| --- | --- | --- | --- |
| 问题 | 用户目标、变量语义、观测范围、资源约束 | 界定能观测什么、需要辨识什么、哪些现象可反驳模型 | ResearchQuestion；不能检验的子问题明确保留 |
| 文献证据 | 检索问题和候选方法 | 检索并打开原文，提取方法条件、失败条件、代码/数据入口 | EvidenceRecord，含来源位置、版本和内容摘要；预置目录不算已完成新检索 |
| 假设 | 观测和已读证据 | 提出竞争解释与互相区别的预测 | HypothesisSet；每项至少有一种可能推翻它的实验 |
| 实验 | 假设、观测与允许的实验接口 | 生成并执行拟合、主动采样或诊断代码 | ExperimentRecord，真实代码摘要、输入、预算、输出和退出状态 |
| 反驳 | 训练外残差、竞争模型和已有失败 | 寻找两模型分歧最大的初值/激励；执行反例；分析方法失败是否可重复 | Counterexample，必须链接真实实验，不得只写批评段落 |
| 修订 | 反例与文献约束 | 改写科学方法源码、实验计划或观测策略；先在公开 development 修复 | RevisedHypothesis 与新代码版本；保留被推翻路径 |
| 复现 | 冻结的获选方法和产物 | 新环境、独立种子/观测、同一方法重新拟合与预测 | ReplicationRecord；失败不得被后续文字覆盖 |
| 结论 | 以上全部证据 | 区分预测支持、方程结构支持、失败和不可辨识 | ResearchSubmission；每项 claim 指向 evidence/experiment/replication |
| 自改进 | 多任务 Episodes、真实源码和版本档案 | 执行当前 improver 修改 Task 或自身源码，再让候选实际跑研究任务 | CandidateBundle；独立 Task 和真实后代生产力评价 |

科学任务中可以有自适应工作流，阶段可往返或并行；验证器核查必要证据关系，不强行把每次研究写成同一条线性脚本。
可编排角色包括证据研究员、理论/建模员、实验设计员、实现员、反例研究员和独立复现员。任务程序可以修改这些角色的提示、工具选择和路由，控制器只掌握预算与可信执行记录。

## 6. 源码级输入输出 API 建议

以下为系统职责层面的建议契约。实际首版函数名与消息结构以[共享源码运行契约](source-runtime-contract.md)为准：源码包使用 `files` 中的 `task.py`、`meta.py`、`workflow.py`，真实入口为 `solve(problem, tools)` 和 `improve(context, broker)`。下列抽象接口用于解释职责，不是声称已经实现另一套同名 API。JSON 用于跨进程消息；它描述代码与研究产物，不把可搜索算法缩成固定枚举字段。

```python
class ProgramBundle:
    manifest: dict       # version, entrypoints, dependency lock, parent digest
    task_sources: dict[str, str]
    improver_sources: dict[str, str]
    prompts: dict[str, str]
    code_digest: str

async def run_research(task: ResearchTask,
                       context: ResearchContext) -> ResearchSubmission:
    ...

async def improve(parent: ProgramBundle,
                  episodes: list[DevelopmentEpisode],
                  archive: ArchiveView,
                  context: ImprovementContext) -> list[CandidateBundle]:
    ...

def evaluate_submission(submission: ResearchSubmission,
                        private_case: PrivateCase,
                        protocol: EvaluationProtocol) -> EvaluationReceipt:
    ...  # trusted grader; agent cannot invoke it on private_case

async def evaluate_improver(improver: ProgramBundle,
                           contexts: list[MetaAssayContext],
                           budget: Budget,
                           seed: int) -> ImproverReceipt:
    ...  # runs the actual improve entrypoint, not an alternative implementation
```

### 6.1 ResearchTask 和 ResearchContext

| 字段或能力 | Agent 可见内容 | 不得夹带的内容 |
| --- | --- | --- |
| `question` | 科研目标、变量含义、可检验范围 | 基准答案或真实方程模板 |
| `observations` | 每条时间序列、采样时间、观测变量、单位、缺失标记 | 未观测状态、隐藏未来轨迹或无噪真值 |
| `public_context` | 公开实验条件、可用输入信号、已知物理约束 | 能直接编码隐藏参数的任务 ID 或内部生成器名 |
| `literature.search/read` | 经 broker 返回的原始来源与片段、可引用位置 | 候选自己伪造的“检索成功”回执 |
| `experiment.request` | 允许的初值、外部激励、时长、采样与重复次数；返回新的带噪观测 | 真方程、真导数、内部参数；超出传感器能力的隐变量 |
| `workspace.execute` | 工作区中的科学代码、公开数据和可安装的冻结依赖 | 评价器模块、凭据、其他运行产物和隐藏测试文件 |
| `agents.spawn` | 有预算的专业任务、有限上下文、真实调用回执 | 绕过总预算的额外模型端点 |
| `budget/status` | 剩余模型、CPU、实验次数、时间与内存预算 | 提议者修改上限或重置计费的权限 |

隐藏方程族标签不传给科研 Agent；必要的物理语义可以明确给出，但应对所有实验臂一致。
所有新实验都通过 broker 生成并记账。读取源码和修改自己的 Task/Improver 是任务能力；读取评分器或其他用户文件不是科研输入。

### 6.2 ResearchSubmission 和独立评分

`ResearchSubmission` 至少包含：

- `predictor`：模型文件、依赖锁和入口，例如 `vector_field(t, x, u)` 或 `predict(times, initial_state, inputs)`；若目标是其他科学任务，由适配器声明输出契约。
- `hypotheses`：候选、预测、失效条件、当前支持状态。
- `evidence`：真实读取的文献与实验 ID；引用主张和原文位置。
- `experiments`：协议、代码摘要、输入摘要、原始输出路径、实际成本、失败轨迹。
- `counterexamples`：至少一个实际检验竞争解释或检验自身方法的实验；若无法完成则明确缺口。
- `replications`：冻结版本的新运行回执；不能只指向第一次执行。
- `claims`：每项主张的证据链和适用范围。

评分器不接受 Agent 自报的 accuracy、NRMSE 或“已复现”作为通过证据。
它在自己的环境执行提交预测器，比较隐藏轨迹/干预结果，并核对实验回执。
模型对象可使用科学库、复合方法或新源码；不要求只能在 linear/quadratic/cubic 字段中选择。

### 6.3 源码与评分隔离

将可修改的 `task/`、`improver/`、`prompts/`、公开数据和工作区挂载给候选；评价器、真值、最终测试和模型凭据不挂载。
模型服务和实验设备由外部 broker 提供带预算的能力调用。导出凭据不进入 Agent 源码或运行环境。
源码执行必须实际约束文件、进程、网络和资源。当前共享契约采用受能力约束的计算语言：AST 语法与属性限制、封闭 builtins、不可逆 CPython audit hook、独立进程、内存/时间/指令限额，以及仅传递公开观测的消息边界。它不是 OS 容器，也不是允许任意 Python 科学程序的通用沙箱。普通子进程或 AST 名称黑名单本身不足以声称隔离成立；后续若开放任意依赖和文件工作区，必须配套 OS 级隔离与单独威胁分析。

新代码快照先完成加载、契约和公开测试，再进入新实例执行；原文件不能边被评估边覆盖。
验证 receipt 由可信运行器签发或保存内容摘要，Agent 的声明与执行回执分开。
最终报告应能从冻结源码、公开输入与可信评价器重新执行，而非仅复读保存的分数。

## 7. 任务、分割与评分设计

### 7.1 让强基线仍有可研究问题

| 层次 | 用途 | 任务变化 | 主要评价 |
| --- | --- | --- | --- |
| L0 可解析控制 | 检查实现和计分是否正确 | 线性衰减、已知线性振子 | 解析误差、稳定性；不算科研创新 |
| L1 同族新条件 | 连续方法开发与基础迁移 | 新参数、初值、噪声、采样间隔 | 外推轨迹误差、结构恢复、失败率 |
| L2 方法压力测试 | 检验方法是否超出单一最佳配置 | 非高斯离群、缺测、不规则采样、激励变化、不同测量预算 | 噪声鲁棒性、主动实验效率、可辨识性诊断 |
| L3 组合与族外测试 | 科研泛化 | 训练未出现的项组合、非多项式动力学、已声明可观测变量 | 未见机制的预测/结构恢复；与 L1 分开汇报 |
| L4 实际数据或独立科学基准 | 后续领域有效性 | 原始论文公开数据或独立作者任务 | 先完成外部基线复现，再谈新方法收益 |

部分观测会导致不可辨识；生成器应验证可辨识条件，或者将“正确说明当前数据无法区分模型”设为相应任务目标。
不能把数学上信息不足的任务当成必然应答的方程猜谜，再用恰好匹配生成器公式计成功。

### 7.2 数据用途严格分开

| 数据域 | 谁可见 | 用途 | 能否复用 |
| --- | --- | --- | --- |
| `development` | Task、Improver、研究者 | 方法设计、失败归因、候选选择 | 可反复使用，必须承认适应性优化 |
| `meta_development` | 被测 Improver 可见的诊断上下文 | 实际子代生产与 validation 选择 | 单次 Meta assay 内可用；与迁移评估分离 |
| `selection_batch_g` | 可信评价器 | 候选代际选择 | 逐批使用，限制返回反馈；不是终局泛化证据 |
| `meta_transfer_batch` | 可信评价器 | 被测 improver 实际所选后代的迁移收益 | 每轮新批次；只在 assay 完成后释放规定的统计 |
| `confirmation` | 可信评价器 | 候选技术和谱系冻结后的预定复验 | 一次协议一次查看 |
| `final_report` | 可信评价器 | 完成所有方法选择后的终局结论 | 结果一旦用于调试，就退役并重新登记新批次 |

种子至少分为 `evolution_seed`、`task_seed`、`measurement_seed`、`model_sampling_seed`。
时间序列的相邻时间点不能被当作独立样本做随机 train/test 混切。
任务应按系统参数、初值、观测批次和机制划分；同一隐藏轨迹派生的片段不能横跨开发和最终测试。

### 7.3 评分向量与统计单位

1. **主要指标**：隐藏新初值/激励上的归一化预测误差；报告 median、均值、尾部误差和数值失败率。沿用旧有界分数可以作桥接，但不能只留压缩后的均值。
2. **科学结构**：仅在坐标和可辨识条件明确时比较等价方程、有效项 precision/recall、系数误差。预测相近不必然等于识别到正确机制。
3. **可信性**：独立复现率、反例实验完成率、主张与回执一致性。文字格式错误应区别于科学反驳结果。
4. **资源**：全流程模型调用与输入/输出 tokens、可得时的实际费用、CPU/GPU 秒、峰值内存、实验次数和墙钟；失败与重试均计入。

配对单位是独立任务或独立 Campaign seed，不是轨迹内 160 个相关时间点。
保持父子和各实验臂的任务、测量种子、模型版本与预算配对；并保留所有失败。
候选搜索可使用预先固定的多指标排序，但科学结论应展示完整向量，避免用新颖性自评掩盖预测失败。

## 8. 强基线与四臂对照

先构建有竞争力的固定科研 Agent：平滑导数/弱形式、稀疏回归与正则化、合理候选库、独立初值验证、稳定性检查、失败诊断和文献工具。
其数值基线至少包括调优的 SINDy/WSINDy 或同等方法组合。所有调优只使用 development；基线配置、依赖与代码在比较前冻结。
旧 linear/forward 仍可作为易懂的弱控制，但不能作为唯一比较对象。

| 实验臂 | 科学算法源码 | 科研 Agent 编排/工具策略源码 | Improver 源码 | 回答的问题 |
| --- | --- | --- | --- | --- |
| A：强固定 Agent | 固定强方法组合 | 固定，但可在任务内使用工具和已有方法 | 不演化 | 普通强系统在同样资源上能做到什么？ |
| B：Task-only 方法演化 | 可改 | 冻结 | 冻结 I0 | 仅让科学方法源码搜索能产生多少收益？ |
| C：Static-improver Agent 演化 | 可改 | 可改 | 冻结 I0 | 整个科研 Agent 被固定改进器搜索能产生多少收益？ |
| D：Full-RSI | 可改 | 可改 | 可改，并由获选后代继承执行 | 改进器自身演化是否有额外收益？ |

资源紧张时至少保留 A、C、D 三臂；D−C 是“改进器演化”的主要比较，C−B 分析科研编排变化，B−A 分析科学方法搜索。
各臂采用相同模型/版本、工具可用性、初始 Task Agent、公开文献和数据、总实验资源上限。
“相同上限”不代表实际消耗相同，必须绘制质量随实际累计成本变化的曲线。
不得给 D 更多模型调用再把最终绝对分差全部归因于递归机制。

补充因果检查采用 Task/Improver 交叉装配：`(A_old,I_old)`、`(A_new,I_old)`、`(A_old,I_new)`、`(A_new,I_new)`。
它能检查新 Improver 的效果是否只依赖它自己的特定 Task Agent，以及组合是否有额外交互作用。

## 9. 实际后代生产能力评价

### 9.1 被测对象必须是运行中的真实 Improver

从一个包含多个强弱水平、不同失败模式的父代档案取共同起点 `A_j`；不能每次只用同一条线性弱种子。
分别冻结 `I_old` 和 `I_new` 的源码，对同一个 `A_j`、同一份公开失败 Episodes 和同一资源预算实际运行 `improve`。
此 assay 内固定被测 Improver，以隔离其产生科研 Agent 的能力；真正允许 Improver 自身继续变化的完整递归运行另外测量。

```text
for common_parent A_j, independent_seed s:
    for frozen_improver I in [I_old, I_new]:
        archive = clone(A_j)
        run real I.improve(archive, development_episodes, budget=B)
        materialize, load and execute every produced child source bundle
        record invalid patches, failed runs, model calls and compute
        select A_star only by development validation, including incumbent
        score A_star and A_j once on the same private transfer batch
        retain the signed transfer difference and all costs
```

定义：

`M_B(I) = mean_{j,s}[ Q_transfer(A_star(I,A_j,s,B)) - Q_transfer(A_j) ]`。

`A_star` 只能按 validation 选出；不能在 transfer 上挑最好子代。
若 validation 获选子代在 transfer 上更差，记录负收益，不把差异截成零。
候选无效和 Improver 崩溃不能从分母删除；失败状态、预算消耗和没有改进的结果都保留。

这与旧 M_old 的核心区别是：实际执行 Improver 的模型调用、证据分析、代码改写、编译、实验和选择；测量的是新源码真正产生的后代。

### 9.2 不让评价成本失控

使用分级证据，而不是对每个无效补丁立刻执行最大规模 Meta assay：

1. 语法、依赖、输入输出与公开最小任务检查；
2. 多任务 development 结果、补丁实质差异与公开回归；
3. 对进入候选档案的少量版本运行实际后代生产测试；
4. 对冻结的候选与基线做多种子确认和最终报告。

这种级联可节省成本，但最终需要与 C 臂做真实等预算比较。
“源代码变了”是机制证据；“新 Improver 的真实后代迁移能力提升”是效果证据，两者都需要。

## 10. 多种子、失败后迭代与完成条件

### 10.1 预定实验阶段

| 阶段 | 推荐起点 | 用途 | 不得宣称 |
| --- | --- | --- | --- |
| 实现复验 | 解析控制、契约测试、公开源代码运行 | 排除数值/执行错误 | 不能因此声称 Agent 或 RSI 已成功 |
| 开发 pilot | 至少 3 个独立演化 seed；所有对照臂 | 估计方差、失败率、成本和可研究空间 | 小样本最优 seed 不能代表稳健提升 |
| 确认实验 | 至少 10 个独立演化 seed 起步；最终数量根据 pilot 的配对方差和预设最小有意义效应确定 | 检验 D−C 与真实 Meta 收益 | 10 并不是自动获得显著性的保证 |
| 独立最终报告 | 冻结谱系、协议和选择；新机制/参数/观测批次 | 验证科研与 RSI 效果是否迁移 | 看完报告继续调参后不能沿用“未见测试”称呼 |

可用配对差值的 pilot 标准差估算所需样本量，例如正态近似的
`n ≈ ((z_(1-alpha/2)+z_power) * sd_delta / delta_min)^2`，并考虑跨任务相关性、多个预先声明的主要比较及预算。
正式分析优先报告配对置信区间和完整分布。不要在反复查看显著性后随意停止；可采用预定批次或事先声明的序贯规则。

### 10.2 失败必须改变研究动作

| 观察到的失败 | 下一步研究动作 | 何时应改变当前假设 |
| --- | --- | --- |
| Patch 无法加载或运行 | 以最小复现定位依赖/接口/资源错误；对 Improver 的补丁生成与测试组织做修改 | 同类失误反复发生说明改进器实现能力不足，不能只追加空泛反思 |
| 均值提高但一类动力学退化 | 保存该失败分支，在新的公开数据上构造反例；消融库、估计、选择和稳定性处理 | 如 C4 的退化被确认，需实质修复而非放松门槛 |
| 开发提高、转移下降 | 检查数据泄漏、机制覆盖、观测噪声、选择偏差；引入新的公开压力测试 | 若增益依赖特定 seed/族，应收回泛化假设并重写方法 |
| 旧式 meta 分数升、真实生产力不升 | 检查被测代码是否实际执行、成本是否配对、子代是否真正继承 | 停用失真的代理作为晋升证据，评价真实 Improver |
| D 与 C 无差异 | 检查 Improver 是否实际被改写/执行，尝试有文献依据的反例规划或档案学习机制 | 完整证据仍无收益时，应承认当前递归设计假设未成立，继续方法研究 |
| 已达到强基线天花板 | 先核对基线和计分，再登记新的有科学意义压力任务或改以样本/成本效率为目标 | 不能降低强基线、削弱任务或以微小噪声增益宣称突破 |

这里没有把“某轮没有正结果”设为交付完成条件。
系统应支持在预算和授权范围内继续诊断、修订、对照与复验；下一轮研究必须有新假设或新证据，不能机械重放相同提示和相同失败。

### 10.3 完成标准分层

**工程层必须完成**：源码级 Task/Improver 的真实执行、读取自身源码、版本化修改、可信独立评分、预算与隔离、完整信息窗口、暂停/恢复、实验和版本证据导出。

**机制层必须证明**：至少两个非平凡源码继承步骤；改变过的 Improver 真实生成下一代程序；Task/Improver 交叉检查能区分各自作用。只改变无效注释、排序元数据或报告文字不算。

**研究效果层必须争取并验证**：在预先声明的对照与预算下，D 相比强静态系统和 C 有有意义的科研收益；真实 `M_B` 有可迁移提升；没有未解释的关键退化；独立多种子复验成立。

若最后一层未达成，保存完整失败证据并继续研究迭代，不用 UI、测试通过或诚实的阴性结论替代用户要求的目标。
这也不预先保证开放式、自加速到任意能力的理论结论；具体科学创新和 RSI 效果要由真实实验建立。

## 11. 给实现者的首批具体任务

1. 建立通用 `ProgramBundle` 与两类源码入口；评估器留在独立可信 package，不能沿用固定字段作为全部改进空间。
2. 将旧 ODE 生成与计分拆成任务适配器的可信部分，科研 Agent 获取观测并自行编写/选择数值方法。
3. 建立证据、实验、反例与复现对象，保存真实工具回执；替换只显示阶段名称的研究展示。
4. 实现源码候选新实例运行、父代归档、真实 Improver 的后代生产评估及角色/工具编排的可修改入口。

## 12. 当前科学实现与证据边界

新科学模块位于 `src/nexgent/science/`，不导入旧原型。`Toolbox` 提供 JSON 数组上的平滑、导数、任意受限数学表达式特征、连续参数稀疏回归、积分配点、RK4 积分及观测内验证。Task 源码可定义新函数、控制流、项库生成、诊断和参数搜索；工具是可组合基础能力，不代表完整科研 Agent 或完整自改进策略。

模型提交为 `{"terms": [...], "coefficients": [[...]]}`，每个输出分量是表达式项的加权和。数学表达式由 AST 节点闭包解释，不能调用 Python 对象或导入模块。候选不会获得方程族名、真实参数、噪声标签或隐藏未来轨迹；`ResearchBenchmark` 单独产生并评分两个新初值上的较长轨迹。

| 当前实现项 | 实际能力 | 尚不支持的更强声明 |
| --- | --- | --- |
| 科学输入 | 3 条带噪观测轨迹、时间间隔与状态维度 | 没有真实实验设备、任意数据集或文献自动读取能力；这些由研究 broker 提供或后续适配 |

## 13. 晋升阈值的预先审查与统计职责

**成文时间：2026-09-15 15:42:46 UTC（北京时间 23:42:46）之后、本脚本新的 development seeds 0、1、2 运行之前。**
已知信息包括历史 Provider 失败、源码数值单元检查，以及第 12.1 节已打开的 transfer seed 4。下面是基于这些开发证据的协议建议，不能称为完全未看任何数据的设计；尚未查看之后正式多臂研究的结果，也未授权根据正式结果追溯改门槛。具体生效标准应由控制器协议版本和研究开始前保存的 protocol digest 确认。

待审查的两条候选晋升路线为：

| 路线 | 均分要求 | 最差配对单任务要求 | 数值工作要求 |
| --- | --- | --- | --- |
| 质量路线 | Δmean ≥ 0.002 | min Δtask ≥ −0.12 | 不超过共同硬预算 |
| 效率路线 | Δmean ≥ −0.002 | min Δtask ≥ −0.05 | candidate/reference work ≤ 0.85 |

这些阈值可以作为**有限预算下档案探索/工程选择规则**，含义分别是“可测的质量候选”与“近似保质量的数值省工候选”。它们没有自然赋予显著性水平、覆盖率、一般非劣性证明或 RSI 效果证明。尤其均值只增加 0.002 而某任务损失可达 0.12，其允许的权衡较宽；不同任务数量也会改变均值稀释退化的程度。

建议在正式研究开始前补齐以下约束，并冻结是否采纳；这些不应在看到正式结果后临时加入或删去：

1. **失败不可用均值抵销。** 有效父代变成 NaN、预算终止、无模型或爆炸积分时，不能仅靠其他任务补分直接部署。可以保留为探索分支，必须经过反例修复再争取部署。
2. **同族和不同族分别比较。** 除总体和最差任务，显式展示两组均值、失败率与最大退化。若只登记一个总分门槛，不得把通过称为两组都改善；如需每组非劣性保护，建议预先登记组均值不低于 −0.01，并在 pilot 中估计其噪声和可行性后用新协议冻结。
3. **数值省工与总成本区分。** work_units 包括生成、工具与评分，固定数据生成开销会压缩可见省工比例；同时报告源程序数值工作、可信评分与固定生成三项。纯 Python 计算和模型调用不由此完整计量，只有在墙钟、指令/内存及实际模型成本也可比时，才能扩大为“总成本更低”。
4. **固定预算、任务与方向。** 父子使用同一 suite_digest、seed、评价器与硬预算。先记录选择/效应方向，保留所有失败和未晋升候选。档案探索可容许质量/效率 Pareto 权衡，部署冠军和公开研究结论另行标识。
5. **Task 晋升不能代理 Meta。** 上述阈值只能筛科学任务执行程序；改进器源码改变后，仍需按第 9 节真实执行同预算改进器，产生和选择后代，再用独立迁移测量评价。不得把一次 task 提升或省工直接标记为改善自改进能力。
6. **确认效果看独立配对分布。** 正式主比较为 full − static-improver 的独立 campaign seed 配对差及实际后代生产力差；报告置信区间、效应大小和成本曲线。门槛 0.002 是工程分辨率候选值，是否科学上重要须结合 NRMSE、尾部失败和用户目标提前定义。

如果正式研究暴露新失败，下一轮可以修改设计和阈值，但必须记录新版本、解释方法原因、将已查看的测试退役，并对新封存批次重新验证；不能重算同一旧结果直到“通过”。

## 14. 独立固定基线研究脚本

`scripts/run_research_study.py` 当前提供 `baseline` 与 `summarize`，不调用模型服务。执行器、科学模块与两个固定源码包随每次 JSON 结果保存；Python/NumPy/SciPy 版本、协议摘要、每个 seed/case、数值与墙钟成本、失败和真实工具回执均保留。每个 measurement 完成后保存 checkpoint，中断不会删除已有结果。

研究开始前先保存 planned seeds、固定程序、split、预算和顺序，再按种子交替先运行哪一个固定控制。配对统计要求 suite_digest、evaluator_digest 和 task_id 集合一致；缺测或不配对不会被静默排除后继续给出完整区间。
