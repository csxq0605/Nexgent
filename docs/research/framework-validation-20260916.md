# 通用 RSI 框架：实现、真实机制检验与交付证据

本报告检验的是 Nexgent 框架。科学发现和 BBH 分别提供独立的任务环境，不能以某个 demo 的成绩定义框架，也不能以软件检查替代改进器效能证据。

## 1. 已实现的框架边界

Nexgent 核心提供可继承的 `task.py / meta.py / workflow.py / roles.json` 源码包，实际 `solve / improve / select_parent` 进程执行，模型与研究能力代理，预算和事件账本，以及三种公共运行：固定 benchmark、源码演化、实际改进器比较。用户通过信息窗口选择 benchmark、目标和资源，查看研究、实验、源码谱系和独立结果。

领域任务、初始算法、工具、文献、数据和评分分别移到 `nexgent-scientific-discovery` 与 `nexgent-bbh` 两个独立安装包。核心 wheel 的 28 个 Python 文件没有导入两个插件、NumPy 或 SciPy；独立环境未安装这些包，也能打开窗口并在独立进程执行通用源程序。

当前合同见 [架构文档](../architecture.md)，插件入口见 [科学发现](../../benchmarks/scientific_discovery/README.md) 与 [BBH](../../benchmarks/bbh/README.md)。旧 Harness 已从活动产品移除，其历史仍可由 Git 审查。

## 2. 从文献到可检验实现

| 科研依据 | 实现选择 | 所需证据 |
| --- | --- | --- |
| [STOP](https://openreview.net/pdf?id=46Zgqo4QIU)：改进程序自应用 | 后代继承实际 M 源码，由新的进程加载执行 | 源码差异、父子身份、真实 improve 回执 |
| [DGM](https://arxiv.org/abs/2505.22954)：可执行程序档案与探索 | 部署冠军和研究分支分开；可演化的父代选择程序 | 未晋升分支、实际 selector 与后续执行记录 |
| [Hyperagents](https://arxiv.org/html/2603.19461v1)：共同任务起点上的改进器生产率 | 两版真实 M 生成任务后代，开发选择后做独立迁移 | 实际源码、候选、配对分数、失败和成本 |
| 科学实验的干预、对照与缺测原则 | 开发 probe 与独立 meta study 分开；冻结实现/数据/预算；保留失败 | 登记摘要、可追踪实验对象与未筛选的数据 |

本项目提出并实现的组合是**通用 benchmark 接口、智能体可调用的实际后代反馈，以及源码与成本归因**。这些单项机制有明确先例；组合的实现并不证明新理论或普适优势。前一批六项科学 demo 研究未产生不同改进器，促成了本次探测接口和机制审查，原始负结果见 [历史对照报告](source-batch-results-20260916.md)。

## 3. 如何评价改进器

固定 M0、M1、任务起点 T0 和每组资源上限。每个被测 M 实际执行 `improve`，至多使用登记的 k 个生成槽位；候选只按开发结果选取 T*。之后计算独立迁移上的 `imp@k(M) = Q(T*) - Q(T0)`，配对效应为两版 imp@k 之差。模型请求、实际用量、程序执行和领域工作同时报告，不把它们混成未经论证的单一分数。

生成槽位不是合格后代数量。程序正常返回空候选时，任务起点仍被保留，效用可为 0；这不能写成“成功生成一个后代”。进程失败、资源缺测或缺少执行证据则保留 `null`，不补成 0。开发 probe 的结果只能用于后续研究，不能作为未见任务效果。

本轮是两个先后登记的机制 pilot，第二个用于修复第一轮发现的确定性接口缺陷。它们不是两个同分布独立重复，也不构成有统计功效的优势检验。

## 4. 第一轮：发现并保留接口失败

登记 `study-3ae09e74105945a2`，seed 43，两代。模型提出不同的 meta 源码，第二代确实继承执行该源码；任务转移差值为 0。开发配对及两个独立 meta study 均因 459 字符问题直接传入最多 400 字符的检索接口而中断。两组效用不可用，不能解释成零收益。

模型声称修复查询，但源码审查发现只是注释变化，宿主拒绝了该修订。接受的 M1 在第二代没有返回合格后代。源代码继承事实、声称的编排机制和实际效能在这里明确分离。

- 主研究：5 次模型请求，176,736 个已报告 token，22,400 个预留输出 token；未知用量 0。
- 科学独立比较 `study-d57c201e29872ba1`：seeds 491/592，两个配对均不完整，0 新模型请求。
- BBH 独立比较 `study-ba417aca3b24a809`：seed 693，配对不完整，0 新模型请求。

完整 [源码机制审查](framework-mechanism-v1-review.md) 与 [可核对证据](framework-evidence-pilot-v1-20260916.json) 保留全部失败。数值计算并非零成本；不同插件的工作单位单列。

## 5. 修复验证：实际配对运行与候选质量

第二次 [预登记](registered-framework-mechanism-20260916-query-fix.json) 对应 `study-6e02dda373304307`，seed 47，两代。唯一算法干预是把检索请求独立整理为最多 400 字符，模型研究上下文保留完整问题；不改变领域算法、评分或预算。459 与 12,000 字符的真实进程回归均已验证。

主研究完成 16 次模型请求，632,912 个已报告 token，65,600 个预留输出 token，未知用量 0；10 次测量记账 108,622,446 个科学插件工作单位，含源失败路径的保守预算上界，不能全部视为实测数值运算。两代均产生了 meta 源码候选，部署任务保持强基线，最终任务转移差值为 0。

开发 probe `probe-dbda72dadd7344cc` 的两个实际 improve 进程均完成，配对开发增益为 0，正式返回的合格候选均为 0。evolved 组的一个 task trial 因私有名 `_` 未通过源码准入；initial 组的设计与修订均未满足候选对象合同。源码提议、被拒的试验和合格后代必须分别计数。

M1 的 selector 使用了档案没有提供的 `work_units` 字段，实际选择最初节点；第二代因此从初始 M 执行，而非继承 M1 的 improve。该轮的“下一外层代执行改变后的 improve”检查未通过。这是可观察的研究失败，不应由 `meta.py` 已变化这一事实掩盖。

M2 删除了元探测分支、直接调用共用的普通研究流程。它是禁止 import 的设计失败之后的新修订，本身未被开发 probe 测过。详见 [v2 源码审查](framework-mechanism-v2-review.md)。

独立迁移比较均已完成：

| 目标基准与登记 | 种子 | 正式任务候选 | 配对 imp@1 差异 | 模型请求 / 已报告 token |
| --- | --- | --- | --- | --- |
| 科学发现 `study-30cadef88bee7988` | 701、802 | 初始 M 共 2 个；M2 共 2 个；全部进入开发评测 | 两个配对均为 0，无不完整配对 | 15 / 363,491 |
| BBH `study-4ba1dd861ddbeb30` | 903 | 初始 M 为 0；迁入的 M2 为 1 个，进入开发评测 | 0，配对完整 | 8 / 137,335 |

被测 M2 保持其实际源码，BBH 接入替换共同任务起点及领域合同。因此这五个正式任务后代是跨两个插件的实际生成/评测证据。结果没有显示超过任务起点的效用提升。M0 与 M2 在独立比较上下文中都调用共用 `research_cycle`，不能把这次比较描述成已经实现了新的内层角色编排。

开发选择过程解释了零增益的来源：

| 基准 / seed / 改进器 | 后代开发分数 | T0 开发分数 | 实际结果 |
| --- | --- | --- | --- |
| 科学 / 701 / M0 | 0 | 0.803222 | 8 个任务发生 `float * dict` 类型错误 |
| 科学 / 701 / M2 | 0.499125 | 0.803222 | 低于强基线 |
| 科学 / 802 / M2 | 0 | 0.959674 | 8 个任务发生 `KeyError: 0` |
| 科学 / 802 / M0 | 0.959674 | 0.959674 | 同分，保留较早的 T0 |
| BBH / 903 / M2 | 1 | 1 | 同分，保留较早的 T0；M0 没有正式候选 |

五个候选都有匹配源摘要的独立 `solve_batch` 回执。两个科学失败候选是已执行但方法失败的有效 0 分，不是资源缺测。所有组的开发选择最终保留 T0，因此独立迁移 imp@1 为 0；不能从这里推断未被选中候选的独立迁移分数。

两个 pilot 及各自独立比较合计 **44 次模型请求、1,310,474 个已报告 token、180,400 个预留输出 token，未知用量 0**。预留输出上限不是实际 token 或费用。该合计不含前一阶段的六组历史研究，原批成本在其独立报告中列明。不同领域的工作单位不相加。

完整结果见 [v2 证据](framework-evidence-pilot-v2-20260916.json)。生成器将实际 source bundles、未通过准入的 source submissions、正式候选、开发试验、独立评分和调用身份分别存储；以 `call_id` 去重成本，并保留上界记账状态。

## 7. 结论的范围

通用框架及其独立 benchmark 边界已有安装、代码与实际执行证据。元程序源码能被修改；真实配对探测、预算和独立比较已经落到可执行接口。测试与某一条执行链不能推出持续或加速的能力增长。

本轮保留了不生产合格后代、错误父代选择和同一路径比较等负结果。针对元反馈本身的因果优势仍需要相同最终实现下的无反馈/冻结改进器对照和更多独立演化种子；历史 0.7 对照不能直接当作本次 0.8 的同实现消融。受限 Python 运行时也不被表述为完整的操作系统容器。

交付内容包括框架、两个独立插件、信息窗口、论文机制到实现的对应、预登记、真实模型记录与原始证据。研究效应按实际结果报告。
