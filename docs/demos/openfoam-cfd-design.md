## 0. 已实现范围与设计边界

`benchmarks/openfoam` 已作为独立包注册 `openfoam_cavity` 领域与 benchmark。首版只支持冻结的 `split=smoke`、`seed=0`、`cavity_re10`，从官方 Foundation 8 教程复制未修改模板，在宿主管理目录中固定运行 `blockMesh`、`checkMesh`、`icoFoam`。插件解析 400 cells、`Mesh OK.`、求解结束时间和最新 `U`/`p` 内部场，并用内容摘要和宿主 `run.json` 将准备、运行、交付与隐藏评价绑定起来。

真实 WSL2 `Ubuntu-20.04` / Foundation 8 运行的三个命令均返回 0 且未超时；`icoFoam` 到达 0.5 s，`U`/`p` 各解析 400 个有限内部值，独立隐藏评价器接受交付。这说明固定工具链能够准备、执行、解析并验收这一小型官方 case。

这次通过不回答稳态、Ghia 精度、Re=100、网格收敛、时间步收敛、性能、一般 CFD 可靠性或 RSI 效果。normal test 是直接 domain/evaluator smoke；后续另有真实 `TaskService` 执行固定无模型 AgentPackage 的受控拒绝、重试、真实求解、工件和隐藏评价链。后者证明框架恢复路径实际执行，但 0 模型调用，仍不是模型自主恢复或 RSI。以下章节对公共校准和正式实验的要求仍是未来条件，不能从 smoke 结果倒推为已经满足。

## 1. 定位与要回答的问题

Nexgent 是通用完整智能体软件的 RSI 框架。OpenFOAM 提供领域工具、任务输入、物理量和独立评价；智能体自己承担理解目标、分配工作、执行、诊断、修订、复核和交付。CFD 角色名称、固定任务图或网格搜索不应写进通用内核。

本 demo 分别回答：

1. 一个完整 agent 能否在既定预算内完成真实 CFD 工作，给出可追溯、可复现、满足质量合同的结果？
2. 改过编排、技能或记忆策略的 agent，是否在后续任务上更可靠、更节约成本？
3. 改过自改进程序的版本，是否比冻结初始改进器更有能力产生有效后代？

把 `20×20` 改成 `40×40`、调整 `deltaT`、换线性求解容差属于**任务内数值优化**；它们可作为控制组和诊断手段，但不能单独回答后两个问题。本文承接 [产品与重构决策](../design/product-and-refactor-decision.md)、[重构计划](../../REFACTOR_PLAN.md) 和 [完整源包路线 B](../research/reboot-rsi-mechanisms.md#6-路线-b完整源包的群体-hyperagent连编排一起进化) 的主框架边界；不会把旧四文件执行器自动视为完整 agent 软件的实现。

## 2. 为什么先做二维层流顶盖驱动方腔

主任务选 **二维、不可压、等温、层流 lid-driven cavity**。它已有官方 case、几何简单、无需复杂 CAD 或湍流闭合，适合观察版本识别、量纲检查、网格/时间误差、错误诊断、恢复与报告。它不是新流场发现、工程装置认证或聚变验证。

| 阶段 | 场景 | 目的与边界 |
| --- | --- | --- |
| 启动检查 | 原装 Re=10、20×20×1 cavity | 已真实通过固定命令、日志、字段解析和收据绑定；不作为正式准确度或 RSI 结果 |
| 公共校准 | 同一二维层流模型；拟用 Re=10、100 与均匀 20/40/80 网格 | 测量本机成本，确定稳态、网格、时间步和采样误差；本轮仅设计 |
| 正式 demo | 以 Re=100 的方腔问题和冻结任务集合为主体 | 相对于独立参考与质量合同验收 agent 工作；具体任务、预算和阈值须先登记 |
| 后续域内迁移 | 未用于调试的尺度组合、时间分辨率要求、网格约束、可控故障/恢复需求 | 测试流程能否迁移；同一 Re 的相似尺度不等于全新的物理问题 |
| 跨领域框架评价 | 独立 benchmark 插件，任务和工具语义改变 | 更换 cavity 的 Re、网格或长宽比仍是 CFD 域内测试，不是跨领域 RSI 证明 |

正式阶段不直接采用高 Re 湍流、可压流或多物理场来增加“复杂度”；那会引入新模型误差和资源要求，削弱本轮归因。未来若加平板 Couette/Poiseuille 解析解检查，它作为求解/采样技能的补充，不替换本 demo 主场景。

## 3. 版本与物理合同

### 3.1 本机版本决定入口

本机为 **Foundation 8 / `openfoam8 20210316` / `/opt/openfoam8`**。启动模板是 `$FOAM_TUTORIALS/incompressible/icoFoam/cavity/cavity`，本机使用 `icoFoam` 和 `constant/transportProperties`。版本适配必须先读安装事实，再解释字典，不能仅凭产品名字套用其他发行版说明。

| 来源 | 本设计如何使用 |
| --- | --- |
| [Foundation 8 cavity](https://doc.cfd.direct/openfoam/user-guide-v8/cavity) | 主版本的 case、PISO 求解与边界依据 |
| [OpenCFD/openfoam.com icoFoam 文档](https://doc.openfoam.com/2306/tools/processing/solvers/rtm/incompressible/icoFoam/) | 对照不可压瞬态方程与运动学压力语义；不从该版本复制命令或字典覆盖本机 v8 |
| [Foundation 模块化求解器说明](https://cfd.direct/openfoam/free-software/modular-solvers/) | 识别较新版本 `foamRun` 路线，防止与本机 `icoFoam` 混用 |

### 3.2 固定的物理问题

令方腔边长为 \(L\)，顶盖速度为 \(U_0\)，运动学黏度为 \(\nu\)，则

\[
Re=U_0L/\nu,\qquad T_c=L/U_0.
\]

目标模型是

\[
\nabla\cdot\mathbf u=0,\qquad
\partial_t\mathbf u+(\mathbf u\cdot\nabla)\mathbf u
=-\nabla p_k+\nu\nabla^2\mathbf u,
\]

其中 \(p_k=p/\rho\) 为运动学压力，不是直接以 Pa 为单位的压力。`icoFoam` 用 PISO 推进该不可压瞬态问题；这里通过时间推进求取稳态，不将其误称为只求稳态的求解器。[OpenCFD 方程与字段定义](https://doc.openfoam.com/2306/tools/processing/solvers/rtm/incompressible/icoFoam/)

合同固定以下内容，候选不能为获得高分而改变物理问题：

- `x-y` 方形区域，第三方向单层挤出；网格、速度和压力的前后面均为 `empty`。薄三维网格配普通 wall/symmetry 边界不自动等同于该二维模型。单层和退化方向的几何约束须共同检查。[empty 官方说明](https://doc.openfoam.com/2212/tools/processing/boundary-conditions/rtm/constraint/empty/)
- 顶盖 `U=(U0,0,0)`；其他三个壁面无滑移；初始内部速度为零。若正式任务另有初值或连续顶盖启动函数，必须成为新任务身份，不能默默改变。
- 壁面 `p_k` 为 `zeroGradient`，指定压力基准以消除常数自由度。比较压力时还须一致处理 gauge，例如比较去均值后的压力。
- 本机模板 `L=0.1 m, U0=1 m/s, nu=0.01 m²/s` 对应 **Re=10**；相同尺度下 Re=100 要求 `nu=0.001 m²/s`。不得拿 Re=10 输出去比较 Re=100 参考。
- 层流、等温、不可压；不启用湍流模型。顶盖与侧壁交角存在速度边界不连续，不能为了降低误差擅自平滑顶盖后仍声称是同一参考问题。

尺度、黏度、边界、二维约束和采样坐标都进入 case digest。压力基准、输出精度、数值格式也进入复现 manifest。网格和 solver 参数的合法改动范围须在任务合同中公开。

## 4. 启动、开发、保留评价与跨域的隔离

| 数据/场景 | agent 可见信息 | 用途与约束 |
| --- | --- | --- |
| `smoke` | 原装教程、日志、全部输出 | 工具启动与解析调试；不计正式效果 |
| `calibration` | 公共任务及独立参考的校准部分 | 确定可行预算、误差门槛和故障分类；确定后冻结，不混入正式统计 |
| `development` | 任务输入、公共验收指标、真实失败与预算余量 | agent 执行研究和自改进，保留所有候选和失败 |
| `selection` | 独立评估器接收候选；改进器只收到预登记的有限反馈 | 选部署版本；属于研究期间可被适应的评价，不能再充当最终保留集 |
| `final_holdout` | 提交冻结 agent 后执行；参考值/目标输出留在 evaluator | 一次最终评估；结果不回流选 champion；如需根据失败再研究，应登记新研究与新保留任务 |
| `cross_domain` | 新 benchmark 的正常任务输入与工具合同 | 冻结改进器，比较它在另一领域实际生成后代的能力；不以更换网格名冒充跨域 |

确定性 CFD 的任务参数、故障计划与模型采样 seed 是不同东西。登记中分别保存 **独立演化 run seed**、**任务/场景 ID**、**重复执行编号**、**调度/故障计划 ID**。同一方腔换三个 seed 不提供三份独立的物理泛化证据。

正式注册必须包含：版本/二进制与依赖身份、模板与任务列表 digest、参考数据 digest、采样协议、误差预算、停止规则、资源预算、失败语义、agent 起点、允许继承的知识、控制组与全部研究 ID。参考解和评分程序不进入可改 agent 工作区；物理目标和公开验收规范仍应可读。

## 5. 正确性证据：参考、收敛和物理一致性

### 5.1 三种证据不能互相替代

1. **执行证据**：程序启动、退出、产生文件。只有退出码 0 不足以说明算对。
2. **数值验证**：网格、时间步和迭代误差受到控制，并与独立数值参考比较。Ghia 等方腔基准属于此层，不是本项目的新物理发现。
3. **物理模型验证**：与有不确定度说明的实验观测比较。本 demo 没有实验设施或实验数据登记，因此不声称完成这一层；更不能外推到聚变。[NASA V&V 概述](https://www.grc.nasa.gov/www/wind/valid/tutorial/overview.html)

### 5.2 外部参考的取得与限制

首选核对原始 Ghia、Ghia、Shin（1982）的方腔数值基准，针对完全相同 Re 与边界比较无量纲中心线速度。其出版信息和摘要已核实；本轮未成功取得全文、未转录数值表，因此**外部参考数据集目前仍未冻结**。[原始论文 DOI](https://doi.org/10.1016/0021-9991%2882%2990058-4)

正式执行前须由合法可用的原始来源建立本地参考：记录页/表/坐标定义、数值精度、获取方式、文件摘要和可分发范围；不能把未核实来源的镜像 CSV 当成真值，也不将未经许可的整张论文表格随仓库打包。来源不可用时，可以完成工具演示和网格研究，但将“独立参考准确度验收”标为未完成。

独立高分辨率求解或另一实现可以补充参考，但必须先单独审查它的收敛与不确定度。用同一 OpenFOAM 版本跑更细网格有助于验证离散误差，仍有共同实现误差，不能单独取代独立参考。参考值有有限精度和数值误差，不视为数学精确解。

### 5.3 网格与时间收敛

拟用同一网格生成族的 `20/40/80 × 同数 × 1` 三网格做公开校准，细化比 \(r=2\)。这组网格只是候选起点，不预先保证处于渐近收敛区；若不满足，记录“收敛证据不足”，不能挑选恰巧接近的两张网格报收敛。

以固定坐标上的同一个标量 \(q\) 为例，\(q_1,q_2,q_3\) 依次来自细、中、粗网格。在同号、非零且大于迭代/采样噪声的相邻差分下，可估计

\[
p_{obs}=\frac{\ln |(q_3-q_2)/(q_2-q_1)|}{\ln r},\quad
q_{ext}=q_1+\frac{q_1-q_2}{r^{p_{obs}}-1}.
\]

三网格 GCI 的绝对误差估计可写为

\[
U_h=1.25\frac{|q_1-q_2|}{r^{p_{obs}}-1}.
\]

需核查渐近性、单调性及 \(p_{obs}>0\)；不满足时保留原始差分，标记该估计不适用。相对指标分母接近零时改用固定物理尺度（速度用 \(U_0\)），不制造极大或极小的百分比。[NASA 空间收敛指南](https://www.grc.nasa.gov/www/wind/valid/tutorial/spatconv.html)

网格族须保持几何、边界和采样坐标一致。收紧时间步、迭代容差和延长积分时间的检验须与网格误差分开：不能一边粗化时间步一边细化网格后声称测到了纯空间阶次。默认 `Euler` 时间离散也不能被报告成二阶时间精度。顶盖角点的不光滑性可能降低局部阶次，不能强行令 `p=2`。

## 6. 原始指标与阈值如何确定

### 6.1 指标定义

评估器独立读取字段和日志；agent 的自报“收敛”“成功”不是分数来源。

| 指标 | 定义/用途 | 不能如何解释 |
| --- | --- | --- |
| 结构有效性 | 字典与量纲、Re、单层 empty、边界、网格正体积与连接关系；检查所有规定字段有限 | 不因求解器能启动而略过物理合同 |
| 中心线速度误差 | 在冻结的 \(x/L=0.5\)、\(y/L=0.5\) 坐标取样；对 \(u/U_0,v/U_0\) 报加权 RMS 与最大绝对误差 | 不靠挑采样点或只比较边界固定值降低误差 |
| 连续性缺陷 | 用压力修正后的面通量求各 cell 的离散散度；\(D_1=(L/U_0)\sum_i V_i|\nabla_h\cdot u_i|/\sum_i V_i\)，另报最大值 | 封闭无穿透壁面的总净流量可天然近零；它单独不足以验证内部质量守恒 |
| 迭代与时间历史 | 各变量初/末残差、迭代次数、Courant 数、线性求解失败、稳态指标曲线 | OpenFOAM 的不同残差定义不与场误差等同 |
| 稳态变化 | \(S=(T_c/\Delta T)\|U(t)-U(t-\Delta T)\|_V/U_0\)，体积加权 RMS 范数；在登记窗口内检查 | 不把到达教程 `endTime=0.5` 自动视为其他 Re 已稳态 |
| 网格/时间不确定度 | 原始三网格量、观察阶次、GCI 适用性；时间步与迭代加严的增量 | GCI 小不等于物理模型已实验验证 |
| 恢复一致性 | 相同源、case 与预算下，中断恢复和连续执行的归一化字段/QoI 差异 | 不只检查恢复进程退出码 |

中心线插值规则与权重预先冻结。角点邻域的壁面应力/涡量受奇异性影响，不作为首轮唯一主指标。若正确的压力修正通量未导出，连续性诊断必须标缺失；不能以任意插值速度的散度冒充相同量。Foundation 8 的后处理功能对象提供残差、Courant 数等能力，具体采样和通量导出配置仍待实现验收。[v8 后处理文档](https://doc.cfd.direct/openfoam/user-guide-v8/post-processing-cli)

### 6.2 从任务容差到冻结阈值

本轮不凭空声明“残差低于某常数就通过”，也没有本机实测通过率。正式阈值按以下顺序确定：

1. 在看候选结果之前定义使用需求的归一化误差目标 \(\epsilon_{goal}\)。例如“中心线 RMS 为顶盖速度的 2%”只能作为**拟议工程目标**，不是已有实测结论或普适 CFD 标准。
2. 为参考/采样、空间、时间和迭代/稳态分别分配误差预算；可登记保守分配 \(1/3,1/3,1/6,1/6\)，总和为 \(\epsilon_{goal}\)。这是本设计的预算选择，需由校准确认可行。
3. 参考精度、插值误差和三网格/时间加严试验给出各项可观察估计。对参考误差未知的点，不宣称有确定的严格误差界；不能把各项统计不确定度未经假设直接平方相加。
4. 用可信公共校准解确定连续性、稳态窗口及迭代阈值，使这些误差小于其分配额。连续性阈值还要关联允许的一个 \(T_c\) 内体积守恒缺陷；不能只复制模板的 `p tolerance`。
5. 冻结阈值、公式、异常规则和校准证据后，才运行正式候选。达不到精度或预算时，登记任务不可行/验证未完成，不能在看到正式结果后放宽阈值。

安全与有效性门槛优先：非有限场、错误 Re、破坏 empty、缺失参考或未稳态不能用“更省时”补偿。通过质量门槛后，报告误差—成本 Pareto 关系与等成本完成率；不先用任意加权总分隐藏物理失败。网格与迭代不确定度的报告原则参考 Celik 等的原始方法论文；本轮仅核实其书目信息，公式实施以已读 NASA 指南为依据。[Celik 等，2008，DOI](https://doi.org/10.1115/1.2960953)

## 7. 成本校准、候选预算预检与恢复

### 7.1 预检在执行前发生

插件先解析候选 case，估算 \(N_c=N_xN_yN_z\)、最小面间距、目标物理时长、输出频率及上限步数。初始时间步可从 \(\Delta t\le C_{target}\Delta x_{min}/U_{bound}\) 估算；\(U_{bound}\) 不是已知场最大速度，实际推进时仍监测 Courant 数。网格加密后不能沿用旧时间步却忽略 Co 增长。

先在独立 calibration 中测量每种代表配置的启动开销、CPU 秒/步、压力迭代分布、峰值 RSS 和写出字节，再用带余量的估计核验完整工作单是否能在预算内完成。也记录 `cells × completed_steps`、压力总迭代等可比较工作量。不能把它们直接叫 FLOPs，不能把估计秒数叫实测耗时。**本文不预报本机“几秒/几分钟完成”。**

超出预算的候选在入场前记为 `budget_infeasible`，保留完整提案和估计依据。已经启动的失败不退款，不自动重复；并行角色/试验共享总预算 lease，不能各自把全部剩余额度当成私有预算。第一次校准优先单进程 case；并行 LLM 协作不意味着同时运行多个高分辨率求解器。

### 7.2 成本账本必须分项

- 模型：call ID、请求/完成状态、已预约与已报告 tokens；不存密钥到 agent 工件。
- 领域进程：工作单 ID、命令参数、case/source/environment digest、PID、起止时间、wall/CPU 秒、峰值 RSS、写出字节、退出码。
- 数值工作：网格数、已完成/预期步数、压力迭代数、实际采样/后处理成本。
- 停止或缺失：区分实测成本、上界预约、估计以及不可得；“未缓存记账”不能统一称为实际运算量。
- 缓存和恢复：同身份的已完成工件复用有明确引用，不能在物理成本里重复记为一次新仿真；不同工作单仍保留其逻辑工作与资源占用。

### 7.3 恢复不是重新跑一遍

每次运行有不可变输入 manifest 与专属目录；原装教程和既有 case 只作输入。停止时记录最后一个经过完整性检查的输出时间、所需场、字典与网格摘要。仅在源/网格/边界/物性身份一致、检查点完整时恢复；更改模型或网格必须成为新执行，不能悄悄沿用旧场。

连续与中断恢复各有独立计费轨迹，在相同终点比较场和主要 QoI。位级一致不是先验保证；允许的差异阈值须来自输出精度和独立校准。缺损检查点、未知是否完成的提交保留为缺失/需诊断，不能自动再次付费运行并隐藏第一次失败。

## 8. 用户能够观察到的真实 agent 协作

以下是**拟议工作示例，尚未执行**。角色由完整 agent 程序按任务和预算创建，插件只执行授权工具，不强制固定角色数量或调用顺序。

用户目标示例：

> 在本机 OpenFOAM 8 中完成指定 Re=100 方腔的可复现数值验证；给出中心线误差、网格/时间收敛证据，并在既定预算内处理一次登记的中断恢复。

| 工作单与责任 | 输入工件 | 可观察输出及依赖 |
| --- | --- | --- |
| 主 agent 建立计划 | 用户目标、环境 manifest、任务质量/预算合同 | 可执行工作单、依赖、额度分配；不是一段没有执行身份的计划文字 |
| 物理核对子任务 | case 字典、版本资料、目标 Re | 量纲、边界和模型核对；指出 Re=10/100 混淆时必须引用具体文件 |
| 数值计划子任务 | 冻结 QoI、误差预算、校准成本 | 三网格/时间加严方案、预计可行性；可与物理核对并行 |
| 执行子任务 | 经主 agent 合并的批准 case manifest | 实际求解器进程、日志、场和成本；默认串行协调 CFD 资源 |
| 独立诊断子任务 | 输出工件、失败日志、公共指标 | 证据支持的原因排序、待反驳假设、最小必要修订；不能自行改隐藏目标 |
| 复核/报告子任务 | 完整运行轨迹、已冻结评估结果 | 一致性检查、图表、缺失项与局限，最终交付由主 agent 汇总 |

协作边记录发送者/接收者、工作单与消息 ID、输入输出摘要、版本、状态与成本。接收者必须真实读取对应工件并执行；给一次普通调用贴多个角色名不算多个子任务。共享工作区用于传递可引用的工件，聊天不是唯一交接格式。

### 从失败反馈到跨任务策略变化的例子

假设任务 A 出现“压力残差下降，但中心线曲线仍在变化”：

1. 执行者保留时间历史和场；诊断者比较残差、稳态量 \(S\) 与延长积分后的变化，反驳“单次小残差足以停止”的假设。
2. 主 agent 在 A 内延长积分，这是一次任务内修订，单独计费。
3. 自改进 agent 把**停止决策技能**改成“同时检查字段稳定窗口、残差、参考误差可用性与预算”；把“误差类型、证据引用、适用条件、反例”写入可检索记忆，并决定什么时候委派独立诊断。
4. 在冻结的新任务 B（不同黏度/尺度与未见故障安排）上，真正加载新的技能与记忆策略。比较它是否避免过早报告成功，以及增加多少成本。
5. 通过旧/新代码 × 旧/新记忆对照，区分代码效应、经验内容效应和二者交互。若只给 B 更长上下文或更多预算，不归因为 RSI。

另一个可测试机制是“网格加密后先重算 Co 与全工作单成本，再提交任务”，它改变可复用的前置检查/调度策略；某一次把 `deltaT` 减半本身仍只是任务内参数优化。上述两例都是研究假设，不是已观察到的收益。

## 9. 对照与实际后代生产率

| 研究臂 | 固定什么 | 允许改变什么 | 主要问题 |
| --- | --- | --- | --- |
| 固定强流程 | agent、技能、记忆读写规则 | 按预写规则执行同样的数值试验 | 工程自动化基线能做到什么 |
| 任务内优化 | 同一 agent 和改进流程 | 合同内 mesh、deltaT、solver 数值参数 | 单纯数值调优能带来多少收益 |
| 冻结改进器 | 初始改进器及等预算 | 后代 task agent 的编排、技能、记忆规则 | source search 的收益，排除改进器演化 |
| 完整 RSI | 仅可信运行/评价/预算边界固定 | 完整 agent 与其自改进程序及可声明继承的知识 | 新改进器是否在后续任务持续产生更好的 agent |

额外消融冻结编排或记忆规则，以及做代码/记忆互换；不能把所有变化合成一个无法归因的处理。各臂共享起点、公共先验、任务分布、总模型/仿真预算与失败规则，全部 ID 先登记。实际独立演化重复数依预算校准决定；单个源谱系或重复读同一个流场不作显著性结论。

元评价固定被测两版改进器，从相同 agent 任务起点实际产生至多 \(k\) 个后代；按 development 选，再在保留任务执行。记录实际生成过程、空集、语法/运行失败、有效后代数、达标完成率、成本与选中后代相对起点的增益。不能拿固定网格变异器、源码 diff 数或角色数作改进器能力代理。相同模型预算同时匹配 CFD 预算；超时/被停止产生缺失，正常完成但无改进仍是可观察的零增益。

## 10. 交付与失败分解

正式数值验证任务至少交付：环境/源码/case/参考 manifest，工作单与消息图，原始 solver 和后处理日志，字段或其可复现存储引用，采样 CSV/JSON，质量门槛逐项结果，网格与时间收敛表、中心线图、成本明细、失败和恢复记录，以及说明证据范围的报告。已实现 smoke 的较窄合同只交付 receipt-bound `run_manifest` 和 `verification_report`；它不满足正式任务的数值证据要求。

| 失败类别 | 处理语义 |
| --- | --- |
| 安装、版本、路径或字典不兼容 | 工具/技能失败；保留具体诊断，不当成物理负例 |
| 错误 Re/维度/边界/模型 | 物理合同失败；即使数值稳定也不通过 |
| 发散、非有限场、线性求解失败 | 数值失败；保留已付成本与原始日志 |
| 稳态/网格/时间误差证据不足 | 验证未完成；不是已经算准 |
| 缺失参考、采样字段或解析歧义 | 评价缺失；不自动填高分或零误差 |
| 预算预检不可行、超时、中断 | 资源状态单列；记录已观测与预约成本，未完成质量值为缺失 |
| 报告与工件矛盾、不可复现 | agent 交付失败；源码和操作轨迹用于下一轮研究 |

整个闭环的验收对象是**能执行并改进自身工作方式的 agent**。方腔是否算对、任务成本是否下降、agent 是否真正协作、改进器是否更有效分别报告，不以流场图片替代其中任何一项。
