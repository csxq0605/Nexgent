# 默认项目改进流程，2026-10-04

这一轮把跨任务改进接到默认 Nexgent／Main，移除普通用户必须先配置 benchmark JSON
的前提。没有修改组织提案 demo，也没有增加第二套执行器、发布协议或费用账本。

默认组成真实项目历史回归 adapter 与既有 AutoEvolution：保存反馈、独立拒绝或成员
开发能力后提出候选；原请求及反馈做配对，另一个不同且验收通过的历史请求做 guard。
任务集冻结为宿主工件。没有足够历史时等待；新任务完成后推进。
默认先用已有单组件替换合同；显式项目配置保留多组件编排搜索。
Main 展示提案、失败门控、发布、实际采用和独立用量，自动改进开关跨进程保留。

## 发布与复用的集成结果

使用脚本模型、真实 Main／任务执行器／生成器／回归 adapter／门控／worker／版本存储：
保存反馈后自动生成单组件候选，配对提升并通过 guard，发布 revision 1。新进程的
普通请求实际加载修改并交付；reuse_observed 记录该任务。重复推进不重跑完成阶段。
另一测试使 guard 拒绝，确认自动回滚并完整计入五个根任务的费用。

另外覆盖历史不足零费用等待、反馈／输入冻结、来源与 guard 分离、任务成员能力触发、
开关跨进程保留、零模型预算、CLI 无模型查看、候选伪造同名工件不能替换宿主任务集。
这些说明默认框架链路可运行，不构成真实模型净收益、泛化或递归改进证据。

下一步重点是复杂真实任务中的有效能力／策略发布与跨任务采用，以及已有项目策略
