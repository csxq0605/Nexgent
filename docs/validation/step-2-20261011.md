**模拟了什么。** 回环地址上起一个脚本化的 Claude Messages API 服务端，配假密钥。无界面层经 `@nexgent/sdk` 走完整条链：

- 建项目，添加 .csv 和 .xlsx 两份资料，经 Office 技能读出 .xlsx；
- 首轮用 `write_file` / `str_replace` 写文件，`present` 交付 v1 快照；
- 对 v1 提反馈，修改后交付 v2，v1 快照不变；
- 设定持久目标；
- 停止当前轮，此前已流出的文本保留，长 shell 命令连同子进程一起终止；
- 沙箱拒绝写工作区以外的路径，写 `.env` 触发审批；
- 越过测试阈值后压缩上下文；
- `perProject` 费用上限生效；
- `nexgent export` 导出会话；
- 检查 `.nexgent/` 里搜不到密钥。

桌面层用 Playwright 启动真实的 Electron 主进程，接真实 SDK 和同一个脚本化服务端。流程是：建项目、重新打开，用打桩的文件对话框添加资料，看流式文本和工具块，处理审批对话框，看成果卡片，反馈后看 v2 和差异视图，点停止按钮，改设置页，用无令牌或错令牌调 IPC，最后强杀主进程、重启并续聊。

**任务。** 素材在 `scripts/real-task/step2-sales/`，由 `generate.mjs` 确定性生成：

- `orders.csv` 297 行，里面故意放了 12 条重复订单号、6 条地区为空的记录，以及带千分位的金额；
- `regions.xlsx` 是地区代码到中文名的对照表。

运行分三轮：

1. 第一轮：把两份文件作为资料添加，要求写出可重复运行的 `scripts/build-report.mjs`，生成按地区和月份汇总的 `report/summary.csv` 和 README，然后 `present`。
2. 反馈轮：对 v1 提反馈，要求地区改用中文名、加环比增长、README 写清洗规则。
3. 第三轮：要求 README 补写重复订单的处理方式。模型刚开始流式输出时，驱动进程就被强杀；随后由新进程续聊，完成后交付 v3。

## 失败与缺测

- 失败的用例与原因：Linux run-4 与 Windows 第 5 次运行都没有失败项。之前几次的失败和修复见“经过”和“Windows 补验”。
- 没有测到的部分：
  - Windows 的 `package:win` 安装包没有打过，也没有装过；Windows 上只验证了从源码运行。
  - **真实模型下上下文压缩没有触发**：阈值设为 40 000，每次请求计费的输入约 13k，所以压缩只在脚本化 provider 下验证过（H14）。
  - 真实模型只跑了一个任务，正式依据只有一次运行（run-4），没有成功率或时延分布。
  - 真实模型下没有测 thinking 关、拒答、服务端回退。用户决定步骤 2 不跑 thinking 关。
  - macOS 没有测。
  - 桌面层用的是脚本化服务端；没有在桌面应用里用真实模型跑过。
- 已知但未修的问题：
  - `files.list` 每次都全量遍历项目，超过 5000 个文件会截断，没有缓存，大项目里会慢。
  - 回复里的 Markdown 链接点不开。要在系统浏览器里打开，需要主进程新增一个方法并定一条安全规则。
  - `write_file` 自 #48 起只能新建文件，改已有文件必须走 `str_replace`；但模型仍可能用 shell 写文件，run-4 的三轮里都调用过 `bash`。
  - Windows 上只结束 `electron.exe` 时，它的子进程不会退出，重启会被判为“另一个实例”。测试改为结束整个进程树；真实崩溃时是否会这样未验证。
  - 回放时，成果卡片按顺序对应到 `present` 工具块；如果同一步里并行 `present` 且其中有失败，可能对错。
  - 安装包没有签名，没有自动更新（用户决定放到步骤 2 之后）。
