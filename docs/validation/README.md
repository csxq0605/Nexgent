# 验收记录与证据政策

本目录存放每一步的验收记录。政策来自计划 4.0“证据卫生”与 4.10“测试策略”，目的只有一个：评审者不看 PR 描述也能独立核对每项宣称。

## 规则

1. **每步一份记录。** 步骤 n 通过退出门槛（计划 4.7）时，写一份 `step-<n>-<yyyymmdd>.md`，按 [`TEMPLATE.md`](TEMPLATE.md) 填写；一步未通过时也写记录，结论栏写“未通过”与缺什么。同一步重跑则新开一份，不覆盖旧的。
2. **主分支只保留摘要与 manifest。** `step-<n>/` 目录下放摘要 JSON（脚本化 provider 与真实模型各自的结果、调用数、tokens、费用、unknown 计数）和 `manifest.sha256`；manifest 覆盖该目录下除自身外的全部文件，用 `sha256sum` 生成、`sha256sum -c` 核对。
3. **原始 JSONL 不进主分支。** 请求 / 响应原始记录（账本 JSONL、会话 JSONL）移到 Release 附件；记录正文写明附件名、下载位置和每个文件的 SHA-256，使摘要可回溯到原始记录。原始记录不含提示正文中的密钥；含用户资料的记录在上传前脱敏并注明。
4. **未知结果不算成功。** 用量缺失、进程被杀后无法确认的步骤、审核模型给不出判断的用例，一律记为 unknown 并计数；不用文字 JSON、重复抽样或人工补记替代。
5. **脚本化 provider 与真实模型分开记。** 脚本化 provider 的结果证明机制走通，不证明模型收益；真实模型的结果只对所跑的任务、模型与次数负责。两者各自有命令、运行链接或摘要文件，不混写。
6. **结论边界必须写。** 每份记录写明“本记录证明什么、不证明什么”；没有收益或为负时如实写出。
7. **根 README 只引用有记录的能力。** 一项能力进入根 README 之前，本目录要有对应步骤的记录。

## 目录约定

```text
docs/validation/
  README.md                 本文件
  TEMPLATE.md               验收记录模板
  step-<n>-<yyyymmdd>.md    记录正文
  step-<n>/
    <name>.json             摘要（脚本化 provider / 真实模型）
    manifest.sha256         摘要文件的 SHA-256 清单
```

PR #4 的七份验证摘要在步骤 1 迁入 `step-0-pr4/`，其原始 JSONL 按第 3 条移出主干。
