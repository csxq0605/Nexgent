# 委派资料与普通 Main 交付，2026-10-05

本轮修复一般成员协作时的资料传递，没有改变组织应用的交付格式或评价门槛。

## 实现

宿主把父任务目标与可选 `task.instructions` 保存为成员的
`context.assignment`，避免负责人给出简短子目标后丢掉事实。成员保持自己的
冻结职责、原根预算和缩小的工具权限；私有评价上下文不传递。显式输入工件与
附件分享沿用既有引用检查，重启后的成员保留原分派快照。

默认执行策略的成果复核接收完整的有界任务投影及已经读取的输入，减少只看
最近行动记录造成的错误拒绝。固定独立评价程序保持分离。旧执行包不被启动覆盖。

宿主数值证据检查将事实／步骤等条目交叉引用识别为序号。函数参数、真正的
数量和数值 JSON 仍要求独立计算收据，分类版本写入验收快照。

Main 会话从结构化成果的常见文字字段展示可读解释，完整结构与原始内容仍在
“成果”页和导出中保留；没有修改实际交付、评价输入或工件引用。

## 普通入口验证

创建独立核对成员，成员完成检查；负责人读取其真实成果并汇总。没有预置成员
或手工生成成果。重启后成员及分派资料仍在原任务下。

第一次固定验收因“事实(2)”的序号误判而缺少计算证据。修复后从 Main 的
“继续完成”入口补验收，通过且评分十分。核对执行的调用身份及成果引用均未
改变，成员未重跑。累计十二次模型调用、已报告总 token 50266、零工具调用，
包括修复前验收尝试和补验收，费用记录完整。

记录目录为忽略的 `validation-workspace/assignment-main-20261005`。
此结果证明一般任务可以自主创建成员、传递资料、协作交付并独立验收；成员
仍为任务内成员，没有被手工注册为未来组织，更不代表真实自主 RSI 发布成功。
