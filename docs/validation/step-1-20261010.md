脚本模拟的内容：test-support 的脚本化 Claude Messages API 假服务；A. `nexgent run` 完成一次写文件任务（文件、会话记录、账本、锁释放、`task.outcome`）；B. `nexgent resume` 开启一个长轮次，流到一半时 `SIGKILL` 杀进程；C. 新进程 `nexgent resume` 续聊并再写一个文件，验证上一轮被记为 `interrupted`、`seq` 连续、锁释放、早先历史进入模型请求、账本恰有一条未配对请求。24 项检查全部通过。

单元与集成测试：`pnpm test` 39 个文件、438 项通过、3 项跳过（只在 Windows 上运行的测试在 Linux 跳过），两平台一致。其中覆盖的故障注入：断网（连接被拒）、请求超时与流空闲超时、HTTP 4xx/5xx、流中断开、畸形事件、进程树超时终止、会话文件任意字节截断、子进程 kill。

## 失败与缺测

- 失败的用例与原因：无。
- 没有测到的部分：真实 Claude Platform 调用（含 `between_tools` 映射、服务端回退、拒答处理）；审批提示的端到端交互（验收脚本在非 TTY 下全部按拒绝处理）；`apps/cli/bin/nexgent.ps1` 启动器未执行；macOS。
- 已知但未修的问题：Windows 进程树终止用 `taskkill /T`，没有 Job Object，已脱离进程树的后代进程杀不掉；`perProject` 费用上限只定格式未执行；`pause_turn` 按 `stop` 处理，不自动续跑。

## 结论边界

- 本记录证明：在脚本化 provider 下，`nexgent run` 能完成写文件任务并持久化会话与账本；进程被强杀后新进程能恢复会话并续跑；以上在 Linux 与 Windows CI 上都成立。
- 本记录不证明：真实模型的行为、费用与时延。
- 是否满足退出门槛：否——缺真实模型一次。
