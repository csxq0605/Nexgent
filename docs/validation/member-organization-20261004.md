# 通用成员目录与反馈采用，2026-10-04

本轮实现的是框架成员复用，没有修改组织提案应用的目标格式或评价标准。

## 已实现

- 包内角色作为可复用成员，通过既有 `delegate` 的 `task.agent` 字符串调用。
  职责从任务冻结的包解析，不增加工具权限，仍执行完整委派 Episode。
- 完成的任务成员进入开发选项；规划模型选择后，设计模型概括通用职责和
  协作策略。宿主编译既有 PackagePatch v3，沿用独立配对、激活、发布、回归回滚。
  普通包内策略修改仍使用原有单组件补丁；未调用成员不能凭目录存在通过激活。
- Main“协作”页、CLI `team`、SDK `team()` 展示当前成员与实际任务交付。
  可用 `framework_package(members=...)` 组合初始组织，不能覆盖已有部署。
- 新反馈可以在原版本的终结提案后发起下一轮；旧项目索引原地升级，历史
  提案和冻结反馈保留。同一反馈及已经完成阶段不重复执行。
- Main 可设置根任务模型调用上限。默认普通任务和回归任务均允许四十次
  调用、十六万输出 token；所有成员、成果修正及独立评价共用根预算。
  已创建任务的预算不改变。单个改进提案最多五个根任务，单独计费并显示额度。

## 验证范围

相关回归 101 项通过，覆盖普通 Main、应用组合、包补丁、任务合同、反馈协调和
自动恢复。另有定向检查覆盖 Main 显式预算、旧反馈索引升级和新反馈第二轮。
端到端 Main 集成通过任务内成员执行、职责设计、独立门控发布、重启后处理新任务、
按名称复用成员以及实际成果读取。模型边界在该集成中使用可记账的脚本替身。

真实 MiMo Main 的第一项用户说明任务完成并通过独立验收，质量评分九分。
随后复杂协作任务在旧二十次共享调用额度和验证脚本时间上限下暂停：需求分析
成员已交付，风险检查成员未完成；保留真实任务、成果及费用缺失记录，不能算
完整闭环成功。这促成本轮默认额度与普通入口预算设置的改动。暂停任务的额度
没有被补加，也没有重新执行其未知远端调用；另一个新任务中的重复委派问题见下文。

真实模型运行记录保存在忽略目录 `validation-workspace/team-product-20261004`。
已注册成员的普通 Main 与重启运行另存于 `registered-team-main-20261004`。
真实模型的自动成员发布和未来采用尚不能依据上述脚本替身集成宣称完成。

继续运行旧二十次额度的另一项任务也未交付：先出现远端超时、后出现无效 JSON，
负责人重新创建相近成员，最终预算耗尽。当前运行时已将有已准入但结果未知的
终结传输收据纳入原有恢复路径；负责人随原成员等待恢复，而非再发相近委派。
实际子进程测试验证初次运行与重启均只保留一次远端调用和同一成员，相关
二十八项恢复和任务合同检查通过。已收到完整计费记录的无效 JSON 仍沿用既有
单次格式修复规则；未建立连接的确定性失败不会被冒充未知结果。

已注册组织的真实运行还出现成员再次委派同职责检查的冗余层级。为此普通
TaskSpec 现在包含宿主派生的委派范围和剩余深度，初始执行策略明确成员应直接
完成分派职责；同一执行器仍允许确有不同工作时进一步委派。

新初始执行策略在声明成果齐全后复用现有成果复核来判断结束，避免成员反复
发布却等待额外结束动作。复核拒绝会回到原循环修正，不跳过独立验收。
单成果、复核拒绝后的修正和多成果齐全条件均通过真实 worker 测试；连同原
任务策略检查二十三项通过。原有部署继续使用冻结程序，不被启动覆盖。

首次已注册成员真实运行仍未成功：四十次额度用尽，出现重复检查、再次发布
和单次输出额度耗尽；重启后的任务又遇到 Provider 响应读取失败。费用分别为
四十次调用、已报告总 token 192536，及七次调用、已知总 token 23476（两次费用
未知）。这些失败保留于 `registered-team-main-20261004`，不能算成员闭环通过。
相同任务、成员定义和独立评价已以更新策略重跑，记录目录为
`registered-team-main-v2-20261004`。两个任务均完成实际成员执行和汇总：第一项
调用两位注册成员，重启后的另一项调用同一冻结组织中的一位成员，没有冗余子成员。

首次验收发现另一个通用问题：成果中真实工件 ID 的十六进制数字及行内列表编号
被误判为数值主张。现在只排除宿主保存的真实引用及列表序号；虚构引用、数量、
小数、公式和数值 JSON 仍须独立计算证据。冻结验收快照记录该要求版本。
通过普通 Main 的“继续完成”补做固定独立验收，两项均通过、各评分十分，原成员
和执行调用未重复。累计二十九次模型调用、已报告总 token 123896、零工具调用，
包含修复前的验收尝试和两次补验收，费用记录完整。

最新相关回归二十四项通过，覆盖真实引用分类、应用交付、项目改进、成果结束和
未知委派恢复；另有四项成果结束检查通过，包含最后一次决策发布后仍能进入复核。
这些检查与前述检查存在重叠，不相加为测试总数。

此次真实正向结果证明人工在 SDK 配置的初始成员可以从普通 Main 执行、汇总、
独立验收并跨进程复用。真实模型自主发布成员组织并影响后续任务仍未获正向验证，
不得将初始配置或脚本替身的门控集成冒充自主 RSI 成功。
