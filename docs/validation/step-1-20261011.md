**任务。** 素材是 `scripts/real-task/order-lib/`，一个没有依赖的 Node 库。它有两个 bug，分别在 `src/discount.js`（折扣门槛应包含边界值）和 `src/inventory.js`（同一 SKU 跨行的数量要累加后再检查库存），运行 `npm test` 时 12 项里有 3 项失败。脚本把素材复制到一个新的项目目录，然后：

1. 第一轮用 `nexgent run` 执行：修好源码，让全部测试通过，不许修改 `test/` 下的文件。
2. 第二轮用 `nexgent resume <同一会话>` 执行：新建 `src/shipping.js`，`priceOrder` 返回值增加 `shipping`，更新 README，补测试。

**判定。** 结果全部由脚本判定，不看模型自己的说法：

- 改动前先跑基线，确认确实有 3 项失败。
- 第一轮后：原测试文件的哈希不变；原测试加模型看不到的 `hidden/round1.test.js`，共 14 项全部通过；改动涉及 `discount.js` 和 `inventory.js` 两个源文件。
- 第二轮后：项目自己的测试 18 项全部通过，没有少于原来的 12 项，并且覆盖了运费；隐藏测试 `hidden/round2.test.js` 3 项全部通过；README 提到了运费。
- 会话 JSONL 已保存，`seq` 连续，两个 `turn.end` 都是 completed。
- 账本 8 次请求的开始和结束一一配对，全部 `ok`；两条 `task.outcome` 都是 completed。

**过程。** 第一轮 4 次请求、3 次 `bash` 调用，用时 11 秒。第二轮 4 次请求、3 次 `bash` 调用，用时 23 秒。最终改动见原始记录里的 `final.diff`。

- 失败的用例与原因：无。
- 没有测到的部分：

  - 真实模型下没有测 thinking 开启、中断恢复、拒答和服务端回退。

- 本记录证明：在 Linux 上，通过 Nexgent 入口（`nexgent run` / `resume`），真实 Claude Sonnet 5.5 完成了一个跨文件修 bug、再加功能的两轮任务，结果经独立测试验证。会话以原生 JSONL 保存并成功续聊，账本完整，整个过程没有 Python 宿主参与。脚本化验收在 Linux 和 Windows CI 上都通过。
