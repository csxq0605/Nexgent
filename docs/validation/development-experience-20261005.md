# 改进结果进入后续规划

本轮修复框架的两处缺口：下一轮改进没有收到此前候选的实际结果；执行策略生成器
没有收到规划阶段选定的假设。最近八次公开结果现在从已有记录提取，并随当前规划
冻结。策略和组织生成器接收同一计划、经验和公开发布条件，不另建存储或执行协议。
历史 guard 的任务、资料和答案不进入这份经验。

默认发布也支持效率改善：质量不退化，既有 conservative_work 至少减少 20%。
或者仍按评分提高至少 0.1 发布。成功率 1、费用上限、实际加载、完整测量和无退化
检查继续有效，随后仍执行独立 guard；失败则回滚。消耗是框架的比较代理，不是
供应商货币费用。没有收益的改名、质量下降的省调用、零基线“节省”均不能据此发布。
省略效率字段的既有显式策略保留原序列化身份和质量规则；旧任务、候选和决策不重写。

## 普通 Main 的集成闭环

`test_development_experience.py` 从 Main 发送任务、保存反馈，使第一候选实际执行并
因质量门控拒绝。关闭并重开 Main 后保存新反馈，规划器收到前次假设及拒绝结果，
生成器收到选定计划和同一快照；第二候选经过真实运行时的配对、发布、guard。
再启新进程，新普通任务实际执行已发布包，记录后续采用。重复推进没有额外模型调用。

`test_efficiency_improvement.py` 从 Main 保存反馈并运行普通发布流程。相同质量下
减少冗余调用的候选可以通过效率门控，并在新进程的普通任务中采用；质量下降的
省调用候选拒绝，质量和消耗都没有改善的候选也拒绝。

以上使用产生调用收据的模型替身及宿主 Python 初始策略。成员、工件、运行时、
配对、门控、发布和重启均真实执行，但不是实际供应商模型自主发布的证据。
