# 任务中创建受控技能：当前执行合同

范围说明（2026-09-23）：本文描述既有受限技能编译与委派，不包含模型开发和安装通用工具／服务插件。后者属于[能力内核决策](rsi-capability-kernel.md)和[新计划 C 阶段](../../REFACTOR_PLAN.md)的待实现能力。

Nexgent 的任务图可以在执行中发现缺少可复用的能力，再让模型写出一个技能提案。技能不是隐藏在提示词里的建议：宿主把提案编译成新的不可变 AgentPackage，任务图通过 `delegate` 启动子 Episode，实际加载并运行该技能，再把工件引用送回父图。任务类型由输入决定；核心没有 OpenFOAM、科研或 benchmark 专属分支。

## 路径与边界

```text
任务 → architect 设计 pending DAG
     → coder 生成 TaskSkillProposal（代码、输入/输出 schema、可证伪假设）
     → develop_skill 检查并编译子包
     → delegate 在子 Episode 执行新技能
     → 父图读取子任务产物并交付
```

`develop_skill` 是框架能力，不是一个可任意调用的外部工具。它核验提案引用的父包摘要、技能身份和合同，静态审计源码中的 `context` 调用及字面量工具名，要求工具落在本 Episode 的 lease 中，RPC 方法落在宿主给定的上限内。受控代码执行时还再次检查声明的 RPC／工具上限。新子包保持可追溯的父包和提案摘要；宿主把它绑定到创建者的 Episode 树，独立任务和 Evolution channel 不能直接加载。它既不更改运行中的父节点，也不直接发布跨任务 channel。

执行时有两种明确模式：默认 `direct` 把子包工作流设成 `skill → publish`，适合先验证新能力本身；`planner_preserving` 保持父包的通用规划工作流与 orchestrator 原样，只增加 S 技能声明和源码。后者在委派子 Episode 中让规划智能体从真实包清单读取 `available_skills`，自行决定是否放入技能节点及其依赖。确定性端到端测试证明父任务生成技能后，子规划器提出 `architect → skill → publish`，运行新模块并交回结果；这条路径仍属本次任务，尚非独立任务复用。

要把任务中的能力变成候选，宿主另行核验创建者树 lease、开发反馈绑定、持久编译事件及技能身份，用一个独立版本的改进器把该技能重新表达为 PackagePatch v3，交给现有 GenerationService 的真实生成闭环。候选保留通用规划器，与任务专用子包有不同身份；生成后仍须新任务配对选择、组件加载认证、guard 与显式晋升。Main 使用项目级包 channel，才会在晋升后读取新版本。确定性端到端测试已走通这些步骤和晋升后另一任务的实际加载；测试中的模型与评价器都是替身，不是实际能力增益证据。

图提案仍由同一 pending 子图编译器处理。角色、节点、边、并行与停止取舍由任务时模型选择；示例中的 `coder → develop_skill → delegate` 只是任务需要新技能时可用的路径，不是所有任务的固定模板。编译失败返回可检查的合同错误；对图的有界修复已有实现。`develop_skill` 现在可显式声明修复角色、最多编译次数和每次模型输出上限。只有确定性的提案合同错误进入修复回合；修复角色收到原任务、前一次完整提案和具体错误，必须返回新的完整提案。每次修复都有独立模型账本路径；已完成的修复回执在崩溃恢复时复用，远端结果未知时拒绝重放。这个机制尚未由真实 MiMo 成功验证。

## 已验证和未验证

确定性端到端测试已验证：模型响应进入图编译器，新技能源码进入不可变子包，委派子 Episode 真正加载 `skills/task_time/` 中的模块，并向父 Episode 返回 `answer: 42` 的工件；保留规划器的子任务也能自主选择该模块。另一个完整测试从创建者 Episode 和反馈出发，生成保留规划器的独立候选；配对任务中替身规划器选择已安装技能，候选分数 1.0、父包 0.0，经过激活门、guard 和晋升后，后续普通任务通过 channel 加载该技能并返回 42。这些数字由测试定义的确定性模型与评价器产生，只证明执行与门控路径，**不证明真实模型技能有效或 RSI 收益**。真实 Provider 开发探针及其失败应另记，不得算作独立效果评估。

当前尚缺：真实模型根据任务反馈完成第二次图重写；受控代码以外的能力创建；真实模型成功使用技能提案修复回合；持久会话／消息流；**真实模型**在未见任务上的独立选择、guard、晋升和复用；改进器利用这些证据改变自身策略。任务时反馈只能提出候选，不可把本次任务成功直接升级为通用能力。
