# 任务中创建能力：当前执行合同

Nexgent 的任务图可以在执行中发现缺少可复用的能力，再让模型写出一个技能提案。技能不是隐藏在提示词里的建议：宿主把提案编译成新的不可变 AgentPackage，任务图通过 `delegate` 启动子 Episode，实际加载并运行该技能，再把工件引用送回父图。任务类型由输入决定；核心没有 OpenFOAM、科研或 benchmark 专属分支。

## 路径与边界

```text
任务 → architect 设计 pending DAG
     → coder 生成 TaskSkillProposal（代码、输入/输出 schema、可证伪假设）
     → develop_skill 检查并编译子包
     → delegate 在子 Episode 执行新技能
     → 父图读取子任务产物并交付
```

`develop_skill` 是框架能力，不是一个可任意调用的外部工具。它核验提案引用的父包摘要、技能身份和合同，静态审计源码中的 `context` 调用及字面量工具名，要求工具落在本 Episode 的 lease 中，RPC 方法落在宿主给定的上限内。受控代码执行时还再次检查声明的 RPC／工具上限。新子包保持可追溯的父包和提案摘要；宿主把它绑定到创建者的 Episode 树，独立任务和 Evolution channel 不能直接加载。编译只增加一个受控代码技能并替换子包的工作流；它既不更改运行中的父节点，也不发布跨任务 channel。

图提案仍由同一 pending 子图编译器处理。角色、节点、边、并行与停止取舍由任务时模型选择；示例中的 `coder → develop_skill → delegate` 只是任务需要新技能时可用的路径，不是所有任务的固定模板。编译失败返回可检查的合同错误；对图的有界修复已有实现，技能提案本身尚无同等级的自动修复回合。

## 已验证和未验证

确定性端到端测试已验证：模型响应进入图编译器，新技能源码进入不可变子包，委派子 Episode 真正加载 `skills/task_time/` 中的模块，并向父 Episode 返回 `answer: 42` 的工件。这验证执行路径，不证明真实模型会稳定写出可用技能。真实 Provider 开发探针及其失败应另记，不得算作独立效果评估。

当前尚缺：任务反馈促发的第二次图重写；新角色身份和受控代码以外的能力创建；技能提案的模型修复回合；持久 AgentMessage 合同；新技能的独立评价、准入、跨任务检索和复用；改进器利用这些证据改变自身策略。跨任务保留应进入现有 Generation／Selection／Promotion 门，不可把本次任务成功直接升级为通用能力。
