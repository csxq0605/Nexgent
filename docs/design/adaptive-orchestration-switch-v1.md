# 可进化执行策略：D1 设计检查点

## 当前事实与缺口

普通任务的 `TaskService.run` 已有两条真实路径：manifest v2 的 `orchestrator` 指向 workflow 时运行 DAG 调度器，其他情况运行包的代码入口。Main 种子用 architect 加 pending slot 生成、编译和修订 DAG；代码入口可通过受控 RPC 执行开放循环。两条路径共用 Episode、能力准入、预算和工件，但**任务模型尚不能在同一入口按反馈选择两者**。

`PackagePatch v3` 可以原子改变 `orchestrator`，但其 `activation_targets` 必须等于所有 `changed_ids`。DAG→代码入口时，旧 DAG 组件必须列为变更，却不会在候选执行中加载，因此现有 `EvolutionService._loaded_evidence` 无法把一次合法的后端切换证明为激活。这是当前合同限制，不能把已有 DAG 修订误报成执行策略可进化。

## 目标合同

1. 任务程序可声明或生成多个候选执行策略：DAG 工作流、受控代码入口、以及由任务内反馈决定下一动作的开放循环。策略是 AgentPackage 中有身份和来源的 O 组件，不是固定角色清单。
2. 在任务开始前或显式检查点，智能体生成 `StrategyDecision`：候选身份、可观察任务依据、资源预估和停止条件。系统冻结所选包／组件摘要并写入 Episode 事件；后端运行结果写入 `execution.active_strategy`，包含策略种类、组件 ID、包摘要、源码／图文件摘要、调用和预算收据。
3. PackagePatch 的“修改集合”与“必须执行激活的集合”分开。切换下线的旧策略保留在候选谱系，要求来源与变更合法；候选执行只需证明新策略及实际依赖组件被加载和使用。仍须拒绝把未执行的候选标成收益。
4. 中途重选只允许在已持久化的检查点发生。冻结触发反馈、原策略状态、目标策略和剩余预算；恢复不能重放已完成的模型、工具或外部副作用。新策略要能读取前一阶段的工件，而非隐式共享进程变量。
5. 反馈后跨任务保留沿用 Generation／Evolution 的独立 selection、guard、回滚。模型可提议策略切换，是否晋升取决于未见任务、实际策略激活与完整成本收据。

## 分步实现与可证伪测试

- **D1-A 策略身份与切换补丁。** 引入版本化补丁合同；让 DAG→代码与代码→DAG 都可被验证，同时不放宽工具、effect、并行度和文件所有权上限。定向测试须证明切换后的 `execution.active_strategy` 与真实 worker／DAG 路径一致，旧策略未运行时不会被误报为新策略激活。篡改组件摘要、空激活目标和凭空扩大权限均拒绝。
- **D1-B 任务内选择。** 同一普通任务入口在冻结候选集合内选择 DAG、代码或开放循环，记录一次模型决策和实际后端；无模型调用的确定性试验先验证选择与恢复，再用真实模型任务检查是否能选对。计划错误只能得到诊断和有界修订，不静默换到人工指定的成功路径。
- **D1-C 中途反馈重选。** 至少一项真实任务出现可验证失败或能力缺口，智能体保留已完成工件、换策略并完成任务；中断恢复后调用次数与工件身份不变。失败样本和“无需切换”样本同样保留。
- **D1-D 独立效果。** 与固定 DAG、固定代码、同资源单智能体及仅记忆组比较；按模型 token、工具指令、开发搜索成本、时延、失败率和未见任务质量报告，不以 DAG 节点数或角色数代替收益。

## 与参考工作的对应

- [AutoSci](https://arxiv.org/abs/2605.31468) 的 SciDAG 是可复用的多智能体 DAG 模板，SciEvolve 将反馈写回版本化技能／模板。Nexgent 要把此关系扩展到任务无关的执行策略与能力包；目前只具备任务内 DAG 修订和包候选机制。
- [AFlow](https://arxiv.org/abs/2410.10762) 把代码表示的工作流放进执行反馈搜索；Nexgent 的 PackagePatch 可承载候选，但尚无跨后端搜索和实测优势。
- [ADAS](https://arxiv.org/abs/2408.08435) 的元智能体编写新 Agent 程序，启发把角色、通信、控制流及工具策略作为可执行候选，而不是只改固定提示词。
- [DeepSeek Harness 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) 的作用域能力与可替换 loop 提供内核分层参照；Nexgent 需在其上补独立反馈门与跨任务版本继承。

科学发现／OpenFOAM 仍只是可插拔任务设置。上述合同对任何 BenchmarkAdapter 和普通任务使用同一运行与评价路径。
