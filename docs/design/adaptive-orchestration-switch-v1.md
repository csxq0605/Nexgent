# 可进化执行策略：D1 设计检查点

## 当前事实与缺口

普通任务的 `TaskService.run` 已有两条真实路径：manifest v2 的 `orchestrator` 指向 workflow 时运行 DAG 调度器，其他情况运行包的代码入口。Main 种子用 architect 加 pending slot 生成、编译和修订 DAG；代码入口可通过受控 RPC 执行开放循环。两条路径共用 Episode、能力准入、预算和工件，但**任务模型尚不能在同一入口按反馈选择两者**。

`PackagePatch v3` 可以原子改变 `orchestrator`，但其 `activation_targets` 必须等于所有 `changed_ids`。DAG→代码入口时，旧 DAG 组件必须列为变更，却不会在候选执行中加载，因此现有 `EvolutionService._loaded_evidence` 无法把一次合法的后端切换证明为激活。这是当前合同限制，不能把已有 DAG 修订误报成执行策略可进化。

## 目标合同

1. 任务程序可声明或生成多个候选执行策略：DAG 工作流、受控代码入口、以及由任务内反馈决定下一动作的开放循环。策略是 AgentPackage 中有身份和来源的 O 组件，不是固定角色清单。
2. 在任务开始前或显式检查点，智能体生成 `StrategyDecision`：候选身份、可观察任务依据、资源预估和停止条件。系统冻结所选包／组件摘要并写入 Episode 事件；后端运行结果写入 `execution.active_strategy`，包含策略种类、组件 ID、包摘要、源码／图文件摘要、调用和预算收据。
3. PackagePatch 的“修改集合”与“必须执行激活的集合”分开。切换下线的旧策略保留在候选谱系，要求来源与变更合法；候选执行只需证明新策略及实际依赖组件被加载和使用。仍须拒绝把未执行的候选标成收益。
4. 中途重选只允许在已持久化的检查点发生。冻结触发反馈、原策略状态、目标策略和剩余预算；恢复不能重放已完成的模型、工具或外部副作用。新策略要能读取前一阶段的工件，而非隐式共享进程变量。
5. 反馈后跨任务保留沿用 Generation／Evolution 的独立 selection、guard、回滚。模型可提议策略切换，是否晋升取决于未见任务、实际策略激活与完整成本收据。

## 分步实现与可证伪测试

- **D1-A 策略身份与切换补丁。** 引入版本化补丁合同；让 DAG→代码与代码→DAG 都可被验证，同时不放宽工具、effect、并行度和文件所有权上限。定向测试须证明切换后的 `execution.active_strategy` 与真实 worker／DAG 路径一致，旧策略未运行时不会被误报为新策略激活。篡改组件摘要、空激活目标和凭空扩大权限均拒绝。
- **D1-B 任务内选择。** 同一普通任务入口在冻结候选集合内选择 DAG、代码或开放循环，记录一次模型决策和实际后端；无模型调用的确定性试验先验证选择与恢复，再用真实模型任务检查是否能选对。计划错误只能得到诊断和有界修订，不静默换到人工指定的成功路径。
- **D1-C 中途反馈重选。** 至少一项真实任务出现可验证失败或能力缺口，智能体保留已完成工件、换策略并完成任务；中断恢复后调用次数与工件身份不变。失败样本和“无需切换”样本同样保留。
- **D1-D 独立效果。** 与固定 DAG、固定代码、同资源单智能体及仅记忆组比较；按模型 token、工具指令、开发搜索成本、时延、失败率和未见任务质量报告，不以 DAG 节点数或角色数代替收益。

## D1-B/C 的运行合同（2026-09-24 补充）

先让同一个公开 `execute` 入口真正拥有两种现存执行形态：开放循环代码入口与可修订 DAG。当前默认任务包是 manifest v1 的开放循环；Main 的 manifest v2 是 DAG，`agent/main.py` 只是占位，不能把这两者并列声明就称为动态选择。自适应 Main 包必须包含两条可实际运行的 O 组件、对应源码／图摘要和一个由宿主校验的版本化候选集合。原 `orchestrator` 仅供未启用选择的旧包作为默认路径；旧包行为保持兼容。纯代码编排作为第三种形态需要真实的另一个私有 entry 与处理器收据，不能将开放循环换个标签充数。

启动前的 `StrategyDecision` 由任务模型在冻结候选集合中作出，但包、组件、源码、权限和预算身份由宿主反解并写入 Episode；模型只能给候选 ID、依据、停止条件和资源估计。决策记录至少绑定候选集合摘要、selector 组件与模型调用收据、选中组件及源码摘要、原始预算、选择前后用量与剩余额度。无效选择不得静默落到某条人工指定的成功路径。执行回执必须回指同一决策 ID，`active_strategy` 依据真实 worker／DAG 调用形成，不仅从 manifest 或文件加载推断。selector 的模型消耗计入当前任务预算。

选择及后端进入使用持久状态机：已提交的决策直接复用；已完成 selector RPC 但尚未写入决策时，从同一收据重建；started 而结果未知时暂停等待，不重新请求模型。恢复后的运行不得重置整段 wall-clock 限额或重放已完成模型、工具与外部副作用。失败运行可有“进入了哪条策略”的事件，但不能伪造成功激活。

中途切换另需明确 `StrategyCheckpoint`，只由持久的任务反馈或计划收据触发。它冻结旧策略段、已完成工件、待运行部分、触发依据和剩余预算；新策略只能读取可寻址的 handoff 工件。provider 传输故障和结果未知的外部操作属于基础设施恢复，不得被解释为编排失败而自动切换。每次策略段的节点／RPC 路径和计划状态必须隔离；“继续原策略”也是需留痕的决策。先验证 DAG→开放循环的交接，再扩展反向和第三种形态。

最小可证伪试验：同一包、同一入口在不同冻结任务上分别实际进入 DAG 和开放循环；中断点覆盖 selector 收据完成前后、决策提交前后和首个后端付费调用后，恢复的调用次数与工件 ID 不变；篡改候选摘要、选无权限组件或放大并行／effect 均拒绝。随后预登记一项中途暴露证据缺口的真实任务，保留切换、未切换与失败样本，独立评价最终质量和全部外层成本。没有实际后端交接、没有读取 handoff 工件或额外模型调用解释了全部差异时，不支持编排进化主张。

## 与参考工作的对应

- [AutoSci 论文](https://arxiv.org/html/2605.31468v1)的 SciDAG/SciEvolve 把图模板与反馈更新连接；其[固定版本执行器](https://github.com/skyllwt/AutoSci/blob/6bc834a805a1744959a9983809e5d6f0263ef791/scidag/executor.py)不能作为 Nexgent 已有任务中途跨后端切换的证据。借鉴可复用图与版本反馈，而非假定实现已具备运行时换策略。
- [AFlow](https://arxiv.org/html/2410.10762v4)把代码工作流放进外层搜索与验证，可指导跨任务候选比较；其外层搜索不能替代同一 Episode 的持久交接。
- [ADAS](https://arxiv.org/html/2408.08435v2)生成完整可执行 Agent 并使用有界修复及候选档案，指导程序化 O 候选、来源和修复合同；它本身不提供本框架的副作用恢复。
- [DeepSeek Harness 固定架构](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/docs/architecture.md)区分持久 session 事件与实时 agent 事件，支持将决策／检查点当作可恢复事实；可替换 loop 不等于 Nexgent 已实现逐任务多 loop 选择。

科学发现／OpenFOAM 仍只是可插拔任务设置。上述合同对任何 BenchmarkAdapter 和普通任务使用同一运行与评价路径。
