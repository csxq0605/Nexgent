# Nexgent 主对话与信息窗口设计

日期：2026-09-22。状态：产品界面决策，第一版主对话入口已开始实现。

## 1. 结论

Nexgent 的默认产品入口必须是一个 **Main 对话**。用户用自然语言提交目标、补充资料、追问结果和要求修改；后台由同一套通用任务运行时规划、组织智能体、调用工具、保存工件、验证交付并恢复失败。

任务表单、原始 JSON、资源预算、AgentPackage、benchmark 和 RSI 版本是可审计的高级信息，不应该成为首次打开应用时要求用户填写的内容。它们保留在运行详情、项目工作区和 RSI Lab 中。

当前 `TaskWindow` 是一个有用的执行/证据控制台，但不是 Nexgent 的最终主界面。它把“目标、输入、交付合同、五类预算、工具授权”堆在左侧，把 RSI 通道暴露在顶层标签中，因此仍然像 code harness 操作台。它将被保留为高级控制台，并从默认入口退到二级视图。

品牌统一使用 **Nexgent**。环境变量、Python 包名和历史验证文件中的 `NEXGENT`/`NExgent` 是兼容性标识；面向用户的窗口标题、按钮和文档标题使用 `Nexgent`。

## 2. 外部参考得到的可迁移结论

### 2.1 AutoSci

AutoSci 的稳定分支把 Claude Code/Codex 作为对话运行时，使用技能命令组织从知识库初始化、想法生成、实验设计、实验运行、评价到论文写作的生命周期。它把跨项目结构化记忆作为核心，并把实验状态、知识图谱和 Reader 作为辅助观察面；不是先让用户填写一张编排表再开始工作。参见 [AutoSci README](https://github.com/skyllwt/AutoSci#readme) 及其 [论文入口](https://arxiv.org/abs/2605.31468)。

Nexgent 采用这些**交互和对象边界**：对话作为入口、项目记忆持久化、阶段/运行可观察、工件可追溯、改进机制可审计。Nexgent 不把 AutoSci 的科研五阶段硬编码进核心；这些阶段属于科学发现插件可以提供的一种能力包。

### 2.2 Manyselves

本机 `manyselves` 的 README 明确写出“Users talk to Main only”，其前端实现对应以下结构：

- `frontend/src/features/conversations/ConversationPage.tsx`：Main 会话页面；
- `ConversationWorkspace.tsx`：消息历史、消息编辑器和运行态入口；
- `MessageComposer.tsx`：自然语言、文件上下文、重试和停止；
- `MessageList.tsx`：对话时间线，以及可折叠的 Agent 运行态；
- `Sidebar.tsx`：项目、输入、知识库、模板、输出、运行态、日志和历史。

这正是 Nexgent 需要迁移的产品形态。Nexgent 的核心运行器和 RSI 控制面不同，但 UI 的信息层级应保持同样的“Main 在前、证据在后、内部机制可展开”。

## 3. Nexgent 的界面分层

```text
┌───────────────────────────────────────────────────────────────┐
│ Nexgent · Main                                                │
├───────────────┬───────────────────────────────┬───────────────┤
│ 项目/会话      │ 主对话时间线                  │ 运行详情抽屉  │
│                 │                               │               │
│ 新对话          │ 用户目标                      │ 当前阶段      │
│ 最近任务        │ Main 的计划/澄清/结果         │ 智能体与工具  │
│ 项目输入        │ 工件卡片/验收/失败恢复         │ 事件与依赖    │
│ 知识库          │                               │               │
│ 输出            │ [消息与附件编辑器]            │               │
│ 运行态          │                               │               │
│ 历史            │                               │               │
└───────────────┴───────────────────────────────┴───────────────┘
```

### 默认入口

1. **Main 对话**：用户输入目标或追问；系统将消息转成当前项目中的 Episode，默认采用安全的任务合同和预算。
2. **对话内运行卡片**：显示正在规划、调用工具、等待输入、验证、交付或恢复；用户可以展开查看，但不需要先理解节点图。
3. **成果卡片**：展示交付物、验收状态、来源工件、限制和导出操作。

### 二级工作区

| 工作区 | 内容 | 默认是否展开 |
| --- | --- | --- |
| 项目 | 输入、知识、模板、输出、历史会话 | 侧栏可进入 |
| 运行 | 节点依赖、调用账本、工具工件、恢复记录 | 运行卡片展开 |
| Benchmark | 任务分布、评价器、split、成本和回归 | 高级入口 |
| RSI Lab | AgentPackage、Memory/Skill/Orchestration、候选、选择、guard、回滚、改进器版本 | 高级入口 |
| 设置 | Provider、工具授权、默认资源政策 | 设置入口 |

OpenFOAM 只作为可安装的领域能力/benchmark 出现在项目或任务选择中，不成为主导航和默认任务。科学发现同理。

## 4. 与 RSI 语义的对应

主对话只负责让用户表达目标和接收可验证成果；真正自进化的对象仍由框架控制：

1. **任务内适应**：当前 TaskAgent 根据中间反馈改变计划、协作、工具和验证顺序。
2. **跨任务改进**：Memory、Skill、Orchestration 和受控代码等行为资产形成候选版本，在冻结任务与独立评价下选择、部署或回滚。
3. **改进器递归更新**：Improver 自身作为版本化行为包，通过它实际产生的 TaskAgent 后代效用接受检验。

评价器、权限、预算上限、隐藏 holdout 和回滚守卫属于宿主可信边界，不让 Main 对话或领域插件自行改写。RSI Lab 需要展示这些关系和证据，但不应把它们伪装成普通用户必须操作的表单。

## 5. 当前实现切片与后续演进

第一切片提供 `MainWindow`：

- 默认启动进入 Main 对话；
- 发送一句自然语言即可创建并执行一个通用 Episode；
- 右侧显示运行状态、智能体/工具节点、交付和证据摘要；
- 任务控制台通过“高级控制台”打开，保留完整 JSON 合同、预算、工具授权和 RSI 版本查询；
- `--legacy-research` 继续只用于读取保留的 0.8 研究窗口；
- 没有模型或插件时仍能显示真实的无模型执行、失败和恢复状态，不能伪造模型结果。

后续切片再接入：项目级消息历史、附件上传、澄清回合、benchmark 选择器、RSI Lab 的候选/门控视图，以及 Main 对话对 TaskSpec 的结构化预览。结构化预览应由 Main 自动生成，只有缺少关键约束时才要求用户补充。

## 6. 验收标准

- 首屏不要求填写 JSON、五类预算或 RSI channel；
- 一条自然语言消息可以进入同一个 TaskService/benchmark 运行路径；
- 对话时间线能区分用户消息、Main 计划、运行状态、工件和交付结论；
- 高级控制台仍能查看原始执行证据、成本、失败和版本，不降低可审计性；
- 去掉 OpenFOAM 和 scientific-discovery 插件后，Main 仍能创建通用任务；
- 所有用户可见品牌文本写作 `Nexgent`。
