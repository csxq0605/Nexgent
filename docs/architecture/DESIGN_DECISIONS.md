# Nexgent 设计决定

本文列出 Nexgent 现在仍然有效的设计决定，每条写明定了什么、为什么。括号里的编号是这条决定在原 ADR 中的位置；ADR 原文已不在本仓库，要查原文请到归档仓库 `csxq0605/Nexgent-archive`。文件格式见 [`spec/data-formats.md`](../spec/data-formats.md)，权限与沙箱见 [`spec/permissions.md`](../spec/permissions.md)，成员与钩子见 [`spec/agent-hooks.md`](../spec/agent-hooks.md)，产品与设计定位见 [`PROJECT_POSITIONING.md`](../PROJECT_POSITIONING.md)。

## 1. 仓库与参考

- **以 DeepSeek Harness（DSH）为只读参考重写。** DSH 以 git 子模块登记在 `reference/deepseek-harness`，固定一个提交，不参与构建，也不是运行时依赖。需要时可以复制并改写其中的文件（MIT），改写件头部写明来源，并登记到 `THIRD_PARTY_NOTICES.md`。这样 Nexgent 完整拥有自己的运行时，不受上游预览版本变动牵制。（原 ADR 0001）
- **Cordis 从 npm 取。** 运行架构直接使用 `@deepseek-ai/cordis` 等库；它们是库，不是 DSH 应用代码。（原 ADR 0001）
- **一个仓库只描述一个产品。** 产品是 TypeScript 写的 Electron 桌面应用加 CLI；旧的 Python 与 PyQt 代码已移出，保留在归档仓库，主干不再加 Python。旧数据不迁移，只保留只读导出。（原 ADR 0001）
- **每个包只实现当前需要的部分。** 边界用测试固定，不追求与 DSH 功能对等，也不复制它的多 provider、i18n 与会话格式迁移。（原 ADR 0001）
- **两平台 CI。** Linux 与 Windows 同时要通过；CI 只手动触发，真实模型验收也是手动。（原 ADR 0001）
- **真实模型实验只设预算上限。** 达到上限即停，不以降低门槛换取好看的结果；没有测出的结果如实记为未知。（原 ADR 0001）
- **Python SDK 延后。** 现在只做 TypeScript 的进程内 SDK 与 Electron IPC。（原 ADR 0001）

## 2. 模型

- **走 Claude Platform，默认 `claude-sonnet-5-5`。** 通过官方 `@anthropic-ai/sdk` 调用 Messages API 的流式接口，不做多 provider 抽象。端点默认是官方地址，可由项目配置或环境变量覆盖，测试用它指向本地假服务。（原 ADR 0002）
- **执行默认开启 thinking，effort 默认 `medium`。** `thinking: 'off'` 仍可配置，发送该模型上最低的 thinking 设置；`xhigh` 与 `max` 时一律用自适应 thinking。不发送 `temperature` 等采样参数，不强制 `tool_choice`。（原 ADR 0002、0003）
- **保留 thinking 块。** 模型回复的内容块原样存进会话记录，恢复与续聊时回放，会话历史只追加不改写。被压进摘要的轮次，以及压缩后保留下来的回复，都不再回放 thinking 块，只发文字与工具调用，因为这些块绑定的是压缩前的历史。（原 ADR 0002、0003、0021）
- **拒答与回退。** 模型拒答时不执行该回复里的工具调用，本轮以 `llm/refused` 结束；对官方主机默认开启服务端回退，可关闭。（原 ADR 0002）
- **工具参数流式到达。** 因此不假定参数 JSON 完整，执行前一律按工具 schema 校验；被 `max_tokens` 截断的回复不执行工具调用。（原 ADR 0002）
- **密钥只从环境读取。** 顺序是 `NEXGENT_API_KEY`，其次 `ANTHROPIC_API_KEY`，绝不写进仓库里的任何文件。（原 ADR 0002）
- **用于评判与外部校准的模型可以换更强的。** 默认是同一个执行模型，外部校准用 `claude-opus-5-5`，费用计入学习或测量本身。（原 ADR 0002、0018）

## 3. 长任务稳定

- **模型请求按退避重试。** 429、5xx（含 529）、连接中断与流空闲超时由 provider 在回复内容到来之前重试，遵守服务端的 `retry-after`，默认最多 6 次、单次等待不超过 60 秒，可取消。每次尝试各写一对账本记录，SDK 自带的重试保持关闭，这样每次尝试都有账可查。（原 ADR 0017、0021）
- **调用上限不是错误。** 每轮模型调用默认最多 400 次；上限前的最后一次调用附隐藏提示，让模型收尾并说明做完了什么、还剩什么；到上限时本轮以取消结束，历史完整，用户说一句“继续”就接着做。（原 ADR 0021）
- **输出被截断时续写。** 单次输出默认 64000 token。只有文字时自动续一次；带工具调用时这些调用不执行，各写一条错误结果，说明被截断、请拆成更小的写入；连续截断超过 3 次才结束本轮。每个 `tool_use` 都必须有结果。（原 ADR 0021）
- **压缩按下一次请求的估计输入触发。** 阈值不超过模型窗口的 75%，默认 160k；保留段本身过长时，当前这一轮也要切；请求因提示过长失败时强制压缩一次并重发。摘要请求的转写有总长度预算，给 thinking 留出输出余量。（原 ADR 0021）
- **同一回复里的只读工具并发。** 多个委派也并发；需要审批的调用仍按原顺序串行；结果与记录按调用顺序，不按完成顺序。（原 ADR 0017）
- **编辑工具宽松，提示不禁止 shell 写文件。** `write_file` 可以覆盖本会话读过的文件，或显式带 `overwrite`；`str_replace` 支持替换全部与一次多处编辑；`read_file` 输出带行号。系统提示只说“改文件优先用编辑工具”，不为某个用例写禁令。（原 ADR 0017）
- **搜索按 ripgrep 的语义，用 JS 实现。** 读 `.gitignore`，支持上下文行、输出模式与分页，大文件流式搜索，各平台结果一致。敏感文件的模式收窄（`.env.example` 一类不算），列表与搜索遇到需要审批的文件时在结果末尾写明跳过了哪些，不静默隐藏。（原 ADR 0022）
- **shell 可以后台运行。** 立即返回编号，可读新增输出或结束；超时与取消仍杀整个进程树；输出最多保留约 3 万字符，保留头尾，完整输出写进会话临时目录；会话关闭时回收全部进程。（原 ADR 0022）
- **Windows 上命令经 PowerShell 执行。** 首选 PowerShell 7（`pwsh`）；找不到时回退到 Windows PowerShell 5.1，并提示一次让模型用 5.1 的语法、建议用户安装 pwsh 7。（原 ADR 0022）

## 4. 执行与协作

- **四种执行形态。** `direct`（主对话自己做）、`delegated`（把一个子任务交给一个成员，前台等结果；`fresh` 只带任务说明与资料，`fork` 另带主对话历史）、`team`（Lead 加具名队友、邮箱与任务板）、`workflow`（脚本或声明式图编排成员，同一运行时承载 PTC）。（原 ADR 0004）
- **每个成员是一个独立子会话。** 有自己的锁与会话记录，父会话写成员的开始与结束记录，重启后可以重建“谁做了什么”。成员可以单独恢复与只读查看。（原 ADR 0004）
- **深度只有一层。** 只有根会话能启动成员，成员看不到委派、建队、工作流等协作工具；队友只保留发消息和任务板工具。（原 ADR 0004）
- **资料按 id、文件按路径、成果经 `present`。** 资料目录只读、不复制，所有成员共用同一个项目工作目录。成员用 `present` 交付，成果带成员标识；不指定成果 id 时，只有同一会话里主文件路径相同才追加版本。父会话读完成员成果后自己汇总，并向用户交付最终成果。（原 ADR 0004）
- **继承只收窄。** 成员的沙箱模式不得宽于父会话（宽了就报错，不悄悄降级）；预设的工具范围与父会话可见集合求交。父会话的系统提示不整体给成员，成员的人设来自预设。（原 ADR 0004）
- **成员与主对话用同一套审批规则。** 审批请求进同一个审批代理，询问时写明是哪个成员，成员不单独自动批准或拒绝。（原 ADR 0004）
- **费用按任务树计。** 一个根任务连同它的全部成员共用一份额度，成员的花费算进父会话；预算份额只能再压低某个成员。（原 ADR 0004）
- **取消向下传播。** 父会话的轮次结束或取消时，仍在运行的成员随之取消；队友的状态保留，下一轮可继续。不做轮次结束之后的后台运行。（原 ADR 0004）
- **并发与规模上限。** 同时运行的成员默认最多 4 个，一棵任务树的成员总数最多 16 个，工作流图与团队任务板、邮箱也有上限。（原 ADR 0004）
- **并行前先查写入范围。** 成员写入的文件集合应互不相交；每个成员有独立工作目录，结束时合并，冲突上报给主智能体。（原 ADR 0004、新方向）

## 5. 任务内即时调整

- **运行中可以插话。** 用户在智能体工作时发的消息进入本轮的待收队列，在下一次模型请求前作为用户消息插入；正在运行的命令不打断；“停止”照旧保留。（2026-10-19 新方向）
- **用户原话压缩时逐字保留。** 一个任务里用户的任务、纠正和反馈只追加不删，压缩后原样放回，新的优先，上限 6 万字符。这样跑得再久、压缩过几次，开头定下的约定仍然被遵守。（2026-10-19 新方向）
- **用户中途的话转给正在运行的成员。** 不只告诉主智能体：每个仍在运行的成员（逐层往下）下一步都会收到“用户在主对话里说了……”，由成员自己判断与它是否相关。（2026-10-19 新方向）

## 6. 组织方式

- **每轮开始前由宿主判断要不要组队。** 小任务（没有资料、只有一行、40 个字或词以内）自己做；其余默认组队，并按比例留出“单独做”作对照（开始每 5 个里 1 个，有结论后每 10 个里 1 个）。不靠模型临场判断，因为让模型自己决定派不派是结果波动的主要来源。（2026-10-19 新方向）
- **模型用 `organize` 工具一次声明分工。** 1 至 6 个角色，角色种类只有通用的五种：规划、调查、实现、测试、审查；写明每个角色的职责和谁等谁，能并行的并行，每个成员在自己的工作副本里干活。内置三种分工（主智能体加检查者；规划、并行实现、审查；先调查后实现），模型也可以自定义。宿主据此调用现有的委派、团队与工作流来执行，对模型只露这一个入口。每个成员最后汇报四行：做完了什么、没做完什么、检查结果、卡在哪里。（2026-10-19 新方向）
- **卡住时改组，并写明原因。** 分工没有进展，或这一轮用过成员而检查失败时，提示模型换分工。再次调用 `organize` 必须给原因，原样重来会被拒绝；新分工记下它换掉了哪个分工、为什么换，界面上显示“改了分工：原因”。（2026-10-19 新方向）
- **用户级组织库记住同类任务上效果好的分工。** 位置 `<NEXGENT_HOME>/organizations/runs.jsonl`，只追加。每个非小任务记一条：是否组队、最后的分工、改了几次分工、用户中途纠正几次、检查结果、整棵任务树的花费，之后被返工也会记下。用任务文字的相似词归类（对不上时按做法归类）。一次“顺利”是正常完成、检查没失败、用户中途没纠正、之后没返工，请了外部评审的评分还要不低于 0.7（没有测试也没有用户反馈的任务约 3 成请外部评审，其他约 1 成）；同类里两边各满 5 次后才下结论。组队时在内置分工和本类顺利过的分工里按汤普森抽样挑选，花费越高扣分越多。界面上只说一句“这类任务用了什么组织，比单独做好多少”，没有结论时说“还在比较”。（2026-10-19 新方向，沿用原 ADR 0023 的结局规则）

## 7. 权限与安全

- **命令在系统沙箱里跑。** macOS 用 seatbelt，Linux 用 bubblewrap，实现采用 `@anthropic-ai/sandbox-runtime`，版本钉死。只能写项目目录、会话临时目录和本会话放行的目录；`.nexgent/`、`.git/hooks/`、`.git/config` 不可写；用户数据目录和常见凭证目录不可读写；网络按项目配置，默认开。`full-access` 不进沙箱。命令触犯沙箱时，工具结果写明被拦的操作；模型可以请求不进沙箱重跑，这要审批。（原 ADR 0022）
- **没有系统沙箱就如实说。** Windows、缺依赖的 Linux 上命令只受命令策略约束，会话头与界面各说明一次，不声称有沙箱。`commands.systemSandbox` 可设为 `required`（没有沙箱就不执行）或 `off`，改它要审批，模型不能替自己关。沙箱目前只在 Linux 上实测过。（原 ADR 0022）
- **项目外的路径改为询问。** 读写项目外路径时弹审批，可选“仅本次”或“本会话允许这个目录”，读写分开放行。用户数据目录、凭证目录、系统目录仍直接拒绝。长期放行写项目配置，改它要审批。（原 ADR 0022）
- **命令策略按 shell 语法解析，只有一套实现。** 引号、转义、管道、子 shell、重定向都识别；`bash -c`、`env`、`xargs` 一类包装逐层展开；git 与包管理器先去掉全局选项再取子命令。授权记录的是触发审批的那条简单命令的完整词序列，不是第一个词。提权、删除项目外内容、下载并执行、改系统状态与沙箱外重跑只能“仅本次”。（原 ADR 0022）
- **只读模式能跑只读命令，另有计划模式。** 只读命令表里的命令、且没有写文件的重定向时照常执行。计划模式等同只读，另有一个每次都要审批的 `exit_plan` 工具，批准后切回原定的执行模式。会话中途宿主可以切换模式，模型自己不能切。（原 ADR 0022）
- **权限字段不进能力包，写入要审批。** 审批、费用上限、沙箱模式和能力设置一类的配置，模型改它们总要审批。插件在宿主进程内执行、不受沙箱约束，采用前每次都要用户批准。（原 ADR 0001、0005）
- **费用上限按美元计。** 缓存读、缓存写、输出各按单价折算；中断或出错的请求按已知用量计入，没有用量时按已收到的内容估算并标明；达到 80% 预警。`perTask` 指一个根任务及其成员，另设整段对话的累计上限。（原 ADR 0017）

## 8. 数据与恢复

- **数据放在用户数据目录，不放进用户项目。** 会话、账本、快照、资料副本、学习记录与“本项目总是允许”的授权统一放在 `<NEXGENT_HOME>/projects/<projectId>/`；项目里的 `.nexgent/` 只保留可与同事共享的内容（项目标识和不含授权的配置），避免 `git add -A` 把它们提交出去。旧项目第一次打开时迁移，不自动删除旧数据。（原 ADR 0017）
- **会话是只追加的 JSONL，账本每次请求一条。** 任何记录都不改写历史，回滚也是新增一个修订。具体格式见 [`spec/data-formats.md`](../spec/data-formats.md)。（原 ADR 0002、0004）
- **每个根任务开始时拍内容寻址的快照。** 按内容增量存放，有总量上限并按保留规则回收，用于回退和回放。（原 ADR 0005、0018）
- **能力版本是内容寻址的完整集合，采用历史是摘要链。** 版本是规范化清单的 SHA-256，没有组件时是 `baseline`；采用历史逐个修订、用上一个文件的哈希串成链；每个会话打开时固定一个版本，运行中的采用不影响已打开的会话；回滚是一个新修订，不删除文件。（原 ADR 0005）
- **未知结果不算成功。** 任何没跑完、没测出或打不了分的结果记为未知（评分记 0），已经花的钱照记。（原 ADR 0005、0019、0026）

## 9. 项目规则与经验

- **三个层次分开处理。** 项目规则是用户明确说过的“以后都这样”，每次都给；经验手册是学来的做法，靠随机注入对照判断有没有用；技能库是归纳出的步骤（默认关闭，见第 11 节）。（原 ADR 0018、0023、0024）
- **项目规则单独存、每次都给，不抽签。** 只记用户亲口说成长期约定的内容，只记在项目级，保留具体的单位、格式和数值，但用自己的话重述。范围按用户的话记，由执行模型判断是否适用。每个根任务的第一轮，在注入内容的最前面给出全部生效的规则；规则压过项目里旧文件的说法，只有本任务自己的消息明确提出的要求能压过规则。（原 ADR 0024）
- **拿不准的规则等用户确认。** 反思判断不了某句话是不是长期规则时标为待确认，不注入，在“能力”页列在最前，由用户确认或不要。只针对这一次结果的要求不算规则。（原 ADR 0024）
- **规则有把关。** 只能带用户亲口给出的数值；不得与用户原话共享 24 个以上连续字符；与已有规则相似且没声明取代的视为重复；一次反思新增条数有上限。规则不因运行结果或评价与它不一致而被判错，只有用户后来的话（声明取代的新规则）能改它；自评与反思都把规则当作任务要求的一部分。（原 ADR 0024）
- **规则与现状冲突时问用户。** 范围内已有的测试或代码与规则不符时，两边都不改，用一句话问用户“规则「X」与现状「Y」冲突，以哪个为准”，然后结束本轮；README、注释、示例这类说明文字仍按规则改，不问。新规则在第一次给出的任务里先查一次冲突。自动检查失败而模型只回复文字、没有再调用工具时，说明它已经解释或已经在问用户，本轮不再自动重试（这对任何检查失败都成立）。提问要短，不说“系统检测到”之类的话。（原 ADR 0029）
- **经验手册条目只有一条可复用的做法。** 带适用范围（任务描述的关键词）、状态（试用、启用、下线）和作用域（用户级或项目级）。每个任务结束后在后台反思，对手册做增量操作（新增、修改、点赞、点踩），不整份重写。一次性要求与含原题具体数值的内容不能进手册。（原 ADR 0018）
- **按任务描述检索手册，注入在首条用户消息之前，不放进系统提示。** 用本地词法方法（中英文分词加 BM25），不依赖向量服务；放在系统提示之外是为了不破坏缓存。（原 ADR 0018）
- **模型自己的话只算“用到了”，不能让条目启用。** 结局只认三种来源：用户的明确信号（评分、指出问题的评论、改回或删除成果）、确定性检查、外部评审的校准抽样。同模型自评不算结局。（原 ADR 0023）
- **随机注入对照决定条目的状态。** 试用条目通过相关性门槛时按 0.5 的概率给模型，启用条目按 0.9 的概率给，留出一部分用来发现退化；两种抽签结果都记录。给和不给两组结局已知的任务各至少 3 个、且给的一组均分不低于不给的一组，才启用；给的一组出现用户负面信号或明显更差则下线。（原 ADR 0023）
- **每个任务自评，有单任务花费上限。** 先跑确定性检查，再由评审模型按任务开始时生成并冻结的评分要点打分；预算不够时按优先级取样（有用户反馈的任务，其次检查失败的任务，其余随机抽）。后台学习共用每项目每 30 天的美元预算。（原 ADR 0018）
- **学习默认开，但先告知、有上限、看得见、随应用停。** 第一次使用时告知用户后台会自评和学习及花费上限；花费按美元显示；后台学习在应用进程内运行，应用退出时一起停。项目有两个开关：使用共享的经验，以及把本项目的经验贡献出去。（原 ADR 0017、0018）
- **练习题集来自用户真实做过的任务。** 每题含任务原文、任务开始时的输入快照、冻结的评分要点与用户反馈，按相似度分成训练、选择、留出三份，留出题不给提案与反思看。评分器本身按纪元冻结，不归任何改进机制修改。（原 ADR 0018、0019）
- **评分器的可靠性单独记录。** 产品自评与外部评审在抽样上的一致率低于 80% 时判为“评分不可靠”，依赖自评的自动启用改为等用户批准。（原 ADR 0019）
- **“更省”不算进化。** 质量打平而更省的做法可以启用，但记为省钱，不计入进化次数。“进化了”的说法只有在预先冻结的测量判据满足之后，才能出现在 README 里。（原 ADR 0019）
- **不做任务特化。** 产品代码、系统提示和评审提示里不写只为某个用例或某类任务服务的规则、例子或默认值，每项改动要能说明对任何任务都成立；用例只用来测量。（原 ADR 0013 及项目约定）

## 10. 界面

- **两栏加按需抽屉。** 主界面是左栏（项目、新对话、对话列表、底部“能力”和“设置”）加对话；资料与成果放进按需打开的右侧抽屉，默认关闭；能力和设置各是整页。过程默认折叠成一行摘要，审批是对话流里的内联卡片，最多三个按钮。（原 ADR 0020）
- **术语改人话，只改界面文字。** 例如“经验”“新做法”“启用”“原来的做法”“一次改进”，token 一律换算成美元，token 数作灰字附注。代码与规范里的术语不变。（原 ADR 0020）
- **模型生成、给用户看的文字用界面语言。** 对比结论与错误提示由界面按结构化字段拼成用户的语言，不显示后端拼的英文句子，原文放进“详细数据”。（原 ADR 0018、0020）
- **视觉上克制。** 左栏浅灰，一个强调色，状态用小圆点加文字；字号只用 4 级；深色与浅色两套配色用同一组颜色 token，默认跟随系统，可在设置里固定。（原 ADR 0020）
- **能力页只有一页，安静。** 自上而下：一句总结、“等你看一眼”（只在有事要用户决定时出现）、项目规则、正在用的经验，最底下是折叠的“改进记录”。说明文字放在名称旁的问号里，只有错误和需要用户决定的事才常显；设置页默认只展开通用、模型、权限三组，其余收进“高级”。（原 ADR 0028）
- **不做浏览器访问的 Web 服务。** 界面是 Electron 桌面应用，主进程持有内核，渲染进程经 IPC 调用进程内 SDK。（原 ADR 0001）

## 11. 已关闭的机制

2026-10-19 起，改进不再靠“拿旧任务重放打分”。以下机制已关闭，**代码仍保留**，默认不运行、界面不显示；要重新启用需要另行决定。

- **能力候选、改进作业与重放门控。** 包括 `capability_propose` 候选、改进作业、改进器及其元改进、门控试验与各种采用规则（原 ADR 0005 至 0016，以及 ADR 0019 的门控纪元部分）。对照试用 `capabilities.autoTrial` 默认关闭。能力版本、摘要链与回滚的格式保留。
- **第 2 层技能库。** 从至少 2 个相似的成功任务归纳技能，存在用户级技能库，按版本只追加，靠与手册同一规则的随机注入对照转正（原 ADR 0025）。开关 `learning.skills` 默认关闭。
- **第 3 层离线进化。** 计划、批准、搜索执行指引与检索参数、留出题配对下结论、续跑，以及用户级已采用配置（原 ADR 0026、0027）。只在脚本化运行器与评审下跑通过，没有真实模型的结果，默认不运行。
- **仍在后台运行的是第 1 层。** 经验手册、自评与随机注入对照继续在后台工作，不占界面中心（原 ADR 0018、0023）。

## 12. 证据与文档

- **README 只写有测试或实测依据的能力。** 写清是脚本化模型的测试还是真实模型的实测，证明了什么、没证明什么；没测出的不写成能做到。原始日志不进仓库。（原 ADR 0001、项目约定）
- **真实模型实验等用户开口。** 在用户明说之前不跑，也不去找用户批费用；测试从简，只测改动的包及其依赖方。（项目约定）
- **要改一项决定，就在本文里改，并写明取代了什么。** 过程记录（计划、调研、交接）不进仓库。（项目约定）
